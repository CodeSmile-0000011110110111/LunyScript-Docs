LunyScript Docs

LunyScript is a C# scripting layer for Unity. Add a component to a game object, point it at a script class, and the object does what the script says:

using CodeSmile.LunyScript;

public sealed class Spinner : Script
{
    protected override void Build() =>
        On.FrameUpdate(Transform.RotateBy(0, 0, 35 * Time.Delta));
}

A user writes a Script subclass whose Build() method composes blocks — On.Ready(...), If(health > 10).Then(...), Transform.MoveBy(...) — and those blocks run against game objects at runtime.

The visual surface it commits to is a runtime debugger, not an authoring editor. Simplified scripting works for designers when they can observe a running script and take control of it while the game is running. Observing means reading the running state: which blocks are active, what values feed them, which branch a condition took. Taking control means changing that state from the outside while it runs, rather than stopping the game, editing the script and entering Play Mode again.

LunyScript does not provide a visual authoring surface: no node graph, no flowchart editor, and no way of composing a script by dragging instead of writing C#. A Script is a plain C# class, not a ScriptableObject or a MonoBehaviour.

v1 targets Unity 6.7 LTS, desktop and web, four local split-screen players as the design point and sixteen networked players as the high-end target. It owns seven API families: camera and viewport, player input, animation, audio, particle effects, UI Toolkit, and physics.
