The Input surface inside Build(): names the local player whose actions this script reads. It hides UnityEngine.Input inside a Script the same way Transform hides UnityEngine.Transform.

public readonly struct InputFactory
Expand Details ...

Examples

var move = Input.ForPlayer(0).Vector2("Move");
var fire = Input.Button("Fire");
On.Ready(Input.Pairing.Open(), Input.Cursor.Lock(), Input.Cursor.Hide());

Remarks

Action reads are always one local player's input, never the machine's. There is no member here that reads a key or a device: an action is resolved for one local player, so a four-player split screen reads four players and not one global read that every player shares. That is what the accepted design means by not deriving local players from global device polling. The player is named with ForPlayer(int, string, int), or left out, in which case it is the player bound to the object the script runs on: Input.Vector2("Move") is the settled contract-input-actions answer's default form, and Input.ForPlayer(n) its explicit form. AnyPlayer(string, int) is a shared button. The machine's own state is the exception: Cursor is one lock and one visibility flag, and Pairing and PlayerCount are the machine's local players.

Which backend supplies the actions is a runner service, not a script's business. The Input surface names no package. CodeSmile.LunyScript.Input is the Input System adapter and the only place in the product that references that package; with no adapter installed every action reads its resting value and says so once.

Remarks

The object is bound by Object.Spawn(prefab).ForPlayer(n) or by the Local Player field on its LunyScriptBehaviour. An object bound to nobody reads resting values, which is the settled answer's "an instance without a participant gets an unavailable binding and neutral value; it does not borrow another player".

LunyScriptUsageException

The name is null or whitespace, this script already declares that action as another kind, or the factory is a default one.

PlayerInputFactory

A builder whose four methods declare one action each.

Examples

var fire = Input.ForPlayer(0).Button("Fire");

Remarks

A local player is numbered from 0, which is the first player on this machine. The number is what the configured backend pairs a device with; the person holding it is a participant, and a number is reused after that person leaves. A named player is not accepted here yet: Define has no player kind, and the participant reference kind the settled contract-player-identity answer describes is not built.

LunyScriptUsageException
