The Net surface a script reads the session through: who has authority, whether there is a session, how many peers, how far behind a value is, and the one way to ask the authority to do something.

public readonly struct NetFactory
Expand Details ...

Examples

On.FrameUpdate(If(Net.HasAuthority).Then(Score.Add(1.0)));

Remarks

Everything here is a state, and none of it throws when there is no session. AGENTS.md rule 45: authority, ownership, connection state and latency are what a networked script gets wrong, and a design that hides them produces the "works as host, breaks as client" defect. An offline peer has no authority, is not connected, has zero peers and a round trip of zero, and a script that guards on any of those then does nothing rather than misbehaving.

Authority, not "server". HasAuthority means owner under distributed authority, which is the default topology, and server under client-server. The same script runs unchanged in either; AGENTS.md rule 44.

The three session facts are conditions and the two numbers are number expressions. A condition goes into If(...) and is negated with !, the way every other condition in this API is; a number expression is compared and combined the way every other number is. The proposal this milestone was written from wrote If(Net.HasAuthority == false), which would have needed a second way to negate a condition alongside the ! operator that already exists. If(!Net.HasAuthority) is the same sentence with the operator the API already has.

ConditionBlock

Examples

Remarks

Owner under distributed authority, server under client-server; false while there is no session, and false on every peer for an object that was never bound to a networked object. This is the guard a write to a synchronised variable belongs behind: without it the write is refused on every peer but one, with the message ScriptInstance raises.

Examples

Remarks

Connecting is not connected, and neither is disconnected. The three are separate states because a script that shows "connecting" and one that shows "offline" are showing a player different things; AGENTS.md rule 45.

SecondsSinceUpdate<T>(Var<T>, string, int)

How many seconds ago this peer last received a value for one synchronised variable. Zero on the peer with authority, whose own value is never behind.

public NumberValueBlock SecondsSinceUpdate<T>(Var<T> variable, string callerFilePath = null, int callerLineNumber = 0) where T : struct

A number expression, in seconds.

Type Parameters

Number, Flag or Text.

Examples

On.FrameUpdate(If(Net.SecondsSinceUpdate(Health) > 1.0).Then(FadeHealthBar.Set(true)));

Remarks

This is the per-variable half of rule 45's "latency is a state". A rate-capped variable is stale between sends by design and a SyncCadence.Once variable is stale from the moment after it arrives; both are correct, and this is how a script can say by how much rather than assume.

Exceptions

LunyScriptUsageException

The variable is not one this script synchronises, so there is no arrival for it to be counting from.
