What Camera.ScreenRay(position) returns: the world ray through a screen position, starting on the camera's near plane and pointing into the screen. Along(ray) on a cast travels along it, and Origin and Direction read it.

public readonly struct ScreenRay
Expand Details ...

Examples

var point = Input.Vector2("Point");
When.Input(Input.Button("Click")).Performed(
    Collision.RayCast().Along(Camera.ScreenRay(point.Value)).Into(Ground));

Remarks

A ray is an expression, never a stored value. Each read takes the camera's pose and the position at that moment, so a ray written once in Build() follows the pointer and the camera every frame. A script that keeps one stores ray.Origin and ray.Direction in two Vector3 variables.

The position is in screen pixels from the bottom left, which is what the Input System's pointer reports. Without InView(ObjectBinding, string, int) the ray goes through Camera.main; with it, through the camera on the view's object. A position outside that camera's pixel rectangle reads a zero origin and a zero direction without a report. No camera, a view binding that holds no object, an object with no camera and a disabled camera read the same zeros and are reported once per script type and line.

A camera that renders into a texture takes the position in that texture's pixels. Cinemachine moves the camera, so the ray follows the live rig and any running blend. docs/proposals/screen-rays.md is the contract.

Properties

Direction

Which way the ray points: a world direction of length one, into the screen, read each time the value is evaluated.

public Vector3ValueBlock Direction { get; }

Property Value

Vector3ValueBlock

A spatial value; zero when the ray could not be computed.

Examples

On.Update(Aim.Set(ray.Origin + ray.Direction * 10));

Remarks

An orthographic camera's rays are all parallel to its forward.

Exceptions

LunyScriptUsageException

This ray is a default that Camera.ScreenRay never made, or another script's Build() made it.

InView(ObjectBinding, string, int)

The same position through the camera on a view's object instead of Camera.main.

public ScreenRay InView(ObjectBinding view, string callerFilePath = null, int callerLineNumber = 0)

Parameters

Type Name Description

Supplied by the compiler. Do not pass one: it records the authored line a diagnostic names.
int
callerLineNumber

Supplied by the compiler.

Returns

ScreenRay

A ray through that view's camera.

Examples

var left = Camera.ScreenRay(point.Value).InView(LeftView);

Remarks

The view is the object carrying the Unity Camera that draws it, the object View.For(view) takes. The ray is unchanged, so one ray can be written with two views.

Exceptions

LunyScriptUsageException

This ray is a default that Camera.ScreenRay never made, another script's Build() made it, it already names a view, or view was not declared by this script's Build().
