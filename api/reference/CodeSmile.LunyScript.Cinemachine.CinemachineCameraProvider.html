Remarks

This assembly compiles only when the Cinemachine package is installed. Its assembly definition carries a version define, LUNY_CINEMACHINE from com.unity.cinemachine 3.0.0 or newer, and a matching define constraint, which is the same arrangement CodeSmile.LunyScript.Netcode uses for Netcode for GameObjects and CodeSmile.LunyScript.Services uses for Unity Gaming Services. With the package absent the assembly is not compiled, nothing references this type, and the core's CameraGateway has no provider, so every camera block writes nothing and says so once.

Nothing here reimplements a camera. Framing, damping, noise, blending and collision stay in the rig the author configured; this provider writes which rig a view renders and what a rig tracks, and Cinemachine does the rest. That is what the captain's answer on the camera family requires.

Selecting a rig is Prioritize(), which keeps the authored blend. Cinemachine's brain renders the highest-priority camera on an output channel it listens to, and the transition into it is the blend the author configured. A rig on a channel the view's brain does not listen to is reported rather than silently having no effect.
