FireUnavailableReason

Null when a debugger may run this node's block by hand with SubmitFireBlock(DiagnosticIdentity, int, bool, int); otherwise why it may not.

public string FireUnavailableReason { get; }

Property Value

string

Examples

fireButton.SetEnabled(node.FireUnavailableReason == null);

Remarks

Decided once, when the program is built, from the node and the blocks that hold it. A block runs by hand when one call is the whole of its work: a plain action or an If, outside a routine, a timed work, a state machine, a utility selection, a multi-frame action and a ForEach body, and outside the six contact events, whose blocks may read the other collider only a contact supplies. A condition or a value has no block to run. Whether the lifetime can take the command now is checked again when it is submitted and applied.

OutcomeNode

The node whose outcome and records this node's block writes: this node's own Id, the first placement of the same block object when that object is placed more than once, or -1 for a node that never writes one, such as a condition.

public int OutcomeNode { get; }

Property Value

int

Examples

var outcome = snapshot.NodeOutcomes[node.OutcomeNode];

Remarks

A block that holds no internal slot and no child is placed as the same object each time an author places one block value twice, so both placements run one object and the runtime cannot tell which placement ran. It records both under the first placement in catalog order. docs/execution-model.md, "Reusing a composed block", states which blocks are copied per placement instead.

PreviewUnavailableReason

Null when Preview(DiagnosticNode) can compute what this node says from a snapshot's stored values; otherwise why it cannot.

public string PreviewUnavailableReason { get; }

Property Value

string

Examples

var live = node.PreviewUnavailableReason == null ? snapshot.Preview(node) : default;

Remarks

Decided once, when the program is built, from the node and every part it reads. A built-in condition or value has a reading when it and all its parts read only the script's variables, its internal storage and literals: comparisons, And, Or and Not, flag, number, enum and text tests, arithmetic, the number functions and spatial math over those, and the outcome of a state machine, a group, a collection call, an operation or a navigation move. A block has none, and neither has a condition or value that reads the object, a component, a bound object, the clock, input, the network, a contact, a list or a map, a UI element or a document, nor one written in C# outside LunyScript, whose code the debugger never runs. A player built without DEBUG or LUNYSCRIPT_TRACE computes none.
