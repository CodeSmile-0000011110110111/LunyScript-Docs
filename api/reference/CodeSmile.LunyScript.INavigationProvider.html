Interface INavigationProvider

Namespace
CodeSmile.LunyScript
Assembly
ApiSource.dll

What a navigation backend provides to the NavigationGateway: sending an actor toward a destination, reading its route and movement, holding it in place, and clearing its route. Script code never sees this type; it sees the Navigation surface.

public interface INavigationProvider
Expand Details ...

Examples

runner.NavigationGateway.UseProvider(new FakeNavigationProvider());

Remarks

The shipped backend is Unity's NavMesh. NavMeshNavigationProvider in CodeSmile.LunyScript.Navigation is the one real implementation and the only place in the product that names NavMeshAgent. FakeNavigationProvider is a second real implementation with no navigation mesh, which is what makes every navigation block testable in every gate. The settled contract-targeting-navigation answer asks for "an explicitly configured navigation capability" and no "implicit provider choice", so the C# code that owns the runner installs one with UseProvider(INavigationProvider).

An actor is a UnityEngine.Object. The core cannot name Unity's object model outside GameObjectHost, AGENTS.md rule 24, so an actor reaches the provider as the object a declared input resolved to, or as the object the script runs on, and the provider is what knows whether that object carries an agent. A GameObject, a Transform and any component of the actor are all the same actor.

The gateway owns the attempts; the provider owns none. Which operation drives an actor, what a partial route means for it, and when an attempt ends are decided in the gateway, so every backend applies the same rules. The provider only answers what the backend knows. Every member but Describe() runs on the frame path and must not allocate once an actor has been seen, AGENTS.md rule 29.
