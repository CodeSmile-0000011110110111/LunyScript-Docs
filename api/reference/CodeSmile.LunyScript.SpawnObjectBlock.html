Remarks

The block records the spawn; the runner applies it after the current dispatch. A prefab can carry a LunyScriptBehaviour, and producing such an object runs its Awake inside the call, which re-enters ScriptRunner.Spawn. The runner refuses to be re-entered during dispatch, so an authored spawn takes effect between event invocations, which is also what the settled contract-dispatch-order answer asks for. Object.Create(name) is immediate instead, because a created object carries no script and can re-enter nothing.

The placement expressions are evaluated here, not when the spawn is applied. A position read from a variable is that variable's value at the line the author wrote.

This block itself allocates nothing. It writes one struct into the runner's request list; the object, and everything the prefab carries, is allocated when the runner applies the request, which is AGENTS.md rule 31's first boundary.
