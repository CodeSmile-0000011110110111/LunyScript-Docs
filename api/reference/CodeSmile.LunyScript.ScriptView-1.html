One incarnation of a script, seen from ordinary C# code: its compiled definition, reads of the variables it declared, and observations of their changes. Find<TScript>(LunyScriptBehaviour) returns it.

public readonly struct ScriptView<TScript> where TScript : Script

Type Parameters

TScript

The script type the lookup asked for.

Expand Details ...

Examples

var player = Scripts.Find<PlayerScript>(behaviour);
if (player.Exists)
    healthLabel.text = $"{player.Read(player.Definition.Health):0}";

Remarks

A view identifies one incarnation. It records the runner that runs the script and the instance's generation, so a pooled instance respawned onto another object is a different incarnation and this view never reads it. Exists is false from the despawn on, and a read then returns the value kind's safe default and logs one warning per ended incarnation. That is the settled contract-reference-generations and contract-engine-read-fallback pair; docs/proposals/typed-instance-view.md states the rest.

There is no write through a view. A C# caller changes another script's state by asking it to, with Send(string).

Properties

Definition

The compiled script object, whose variable properties hold the handles this view reads. It stays set after the incarnation ends, and is null for a view that matched no script.

public TScript Definition { get; }

Property Value

TScript

Examples

var health = player.Read(player.Definition.Health);

Remarks

It is the object whose Build() ran, which Script also returns after Awake. A new PlayerScript() is not a definition: its properties were never assigned.

Exists

True while the incarnation this view was taken of is running: not despawned, not respawned as a later incarnation, its object not destroyed, and its runner's session not ended. False for a view that matched no script.

public bool Exists { get; }

Property Value

bool

Examples

Parameters

Type Name Description

Called with the new value. It is not called for the current value; read that with Read(in Number).

Remarks

The check runs once per frame, after every script's On.LateUpdate. When changed is a method of a Unity object that has since been destroyed, the observation ends instead of calling it.
