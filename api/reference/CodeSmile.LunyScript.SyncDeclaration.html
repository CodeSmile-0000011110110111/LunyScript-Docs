One synchronised variable, as the script declared it: which slot holds it, how often it is sent, and the bookkeeping slots the cadence and the staleness reading need. Recorded at build time, read by the program, and never changed afterwards.

public readonly struct SyncDeclaration
Expand Details ...

Remarks

One of these per synchronised variable, which is what AGENTS.md rule 46 requires: state is declared one variable at a time, and there is no networked struct that could carry two of them. This type is that rule expressed in the build output, and it is deliberately not a grouping: nothing here can hold a second variable.

The cadence's own state lives in slots, not in fields on this struct. AGENTS.md rule 23: all per-object state is a slot allocated at build time. One declaration is shared by every object running the script, so "the value I last sent" and "how long until I may send again" are per-object facts and belong in the instance. What this struct carries is the addresses of those slots, which are the same for every object.

StalenessSlotIndex

Which Number slot counts the seconds since this peer last received a value for the variable. Read by Net.SecondsSinceUpdate, and held at zero on the peer with authority, whose own value is never stale.

Remarks

AGENTS.md rule 45: latency is a state a script may read, not an exception it handles. A rate-capped or Once variable is stale between sends by design, and this is where a script can see by how much rather than having to assume.
