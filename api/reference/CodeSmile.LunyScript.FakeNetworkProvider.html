A netcode backend that runs entirely in this process, with no network, no Editor and no Netcode for GameObjects. Two instances are paired with Pair(out FakeNetworkProvider, out FakeNetworkProvider) and each one's sends arrive in the other's queues.

Remarks

This is a second real implementation, not a mock. It is the netcode counterpart of FileCloudSaveProvider, which AGENTS.md rule 52 makes a first-class part of the product because it is how every branch is tested without a service. The message and cadence tests run against this provider with no network and no Editor session, and the same behaviour is exercised against NgoNetworkProvider where a real session is available. TestKit.NetworkProviderConformance is the one list of assertions both providers are held to, so that the double cannot drift from the backend without a test saying so.

Authority here is ownership, which is the distributed-authority meaning. Each object is owned by exactly one peer, set with SetAuthority(int, int). That is the default topology under AGENTS.md rule 44, and a script written against Net.HasAuthority reads the same under either.

Delivery is immediate and ordered. A send lands in the peer's queue before the call returns, so a test observes it on the next drain with no waiting and no frames. That makes the tests deterministic; it also means this provider cannot reproduce a latency or reordering defect, and a test that needs those needs the real provider.

MaximumTransformStreamBytes

How many payload bytes of transform stream this backend can carry in one send. The runner splits a tick's stream into as many sends as it needs to stay inside it.

public int MaximumTransformStreamBytes { get; set; }

Property Value

int

Remarks

A transport carries a bounded message. One stream per authority per tick is what AGENTS.md rule 47 requires and it stays true here: the tick still produces one stream, and this is how many bytes of it fit in one message. A hundred objects sending all three channels is about 1800 bytes, which is past what Netcode for GameObjects carries unfragmented, so this is not a limit only an unusual session meets.

Splitting rather than asking the backend to fragment is deliberate. Each piece carries the stream's own 3-byte header and is decoded on its own, so a piece costs about 3 bytes plus whatever the backend's own per-message header is; a fragmented message costs the backend's fragment headers and its reassembly state instead, and leaves the stream depending on a feature that differs between backends.

How many transform streams this peer has delivered since the session started. EndSession() returns it to zero, so it reads per session and not per instance.

Remarks

Counted here rather than only in a test, because the number of streams and the bytes in them are what AGENTS.md rule 47 is about, and a figure that can only be measured with a network is a figure nobody measures. These two count the stream's own payload; what a real backend adds around it is measured at the transport, which is what docs/netcode-bandwidth.md records.

Only a delivered stream is counted, which is what NgoNetworkProvider counts too: a call made while this provider has no session, or with no connected peer to receive it, is not a send and does not move either figure. The two providers implement one documented property and a reading that meant different things on each would be worse than either meaning.

peerId

Remarks

This is what makes SyncCadence.Once work for a peer that was not there when the value was first set. Without it, a name chosen by the host before anyone joined would never be sent, because Once sends once and a late joiner missed it. The authority answers a join by marking every synchronised variable unsent, so the next tick sends the current value of all of them.

The resend goes to every peer, not only to the one that joined. This milestone has no per-peer addressing: SendVariable(int, int, in NetworkValue) is a broadcast. The cost is one redundant copy of each synchronised variable per peer per join, which is bounded by the number of joins rather than by the frame rate. Per-peer addressing is part of the transform stream milestone, where rule 47's bandwidth budget makes it load-bearing.
