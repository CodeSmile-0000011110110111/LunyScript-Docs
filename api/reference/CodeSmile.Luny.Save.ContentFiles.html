Class ContentFiles

Namespace
CodeSmile.Luny.Save

A game's authored content files, in two named places LunySave chooses: the project's Luny folder beside Assets, which the Editor reads and writes, and StreamingAssets/GameData.luny, the uncompressed archive of that folder a player reads. Every path is relative to the Luny folder, such as "Encounter/room-breach.json".

Remarks

Two named roots, no caller-chosen folder. The captain's path rules of 2026-10-07 keep every LunySave call inside a folder LunySave names; his LunySpawn answers of 2026-10-09 (Q11, Q21) added these two: the project-root database folder Luny/ and its archive. No call here takes an absolute path or a folder of the caller's choosing, reads or writes bytes, or writes StreamingAssets anywhere except the one archive.

Content files. A content file's name ends in ".json" and no folder or file name on its path starts with a dot; a read skips every other file and lists it in Skipped. Each content path follows LocalSave's path rule, and two paths that differ only in case fail the read, because Windows and macOS store them as one file.

LunyData reads content through this class for its consumers, so game code queries LunyData and never reads these files itself; this class is for the Editor tools and agents that author the files.

WriteArchive()

Packages the project's Luny folder into Assets/StreamingAssets/GameData.luny, in the Editor: every content file uncompressed, in ordinal path order, so unchanged content gives the same bytes. The new archive replaces the old one only once it is complete; a read that fails writes nothing.

public static ContentArchiveResult WriteArchive()

Returns

ContentArchiveResult

What was written, or why nothing was.

Examples

Exceptions

LunySaveException

Called in a player.

WriteProjectText(string, string)

Writes one content file in the project's Luny folder, in the Editor: the direct JSON write for agents and tools. The text must be one well-formed JSON value; it is written as UTF-8 to a copy beside the file and replaces the file in one rename, creating its folders.
