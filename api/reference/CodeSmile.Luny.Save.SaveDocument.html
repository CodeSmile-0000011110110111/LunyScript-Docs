The values of one document of a SaveSchema: what Save(SaveDocument) writes and what a successful LoadOperation returns. Each declared field either holds a value or holds none.

Examples

Remarks

A new document holds no value. A save refuses a document that does not hold every declared field, naming the ones it lacks, because a stored copy without them would make the next load report them as omitted. A loaded document holds every field the stored copy could give it; a field the load omitted holds none, so TryGet<T>(SaveField<T>, out T) returns false for it and the caller's value stays what it was, and OmissionReason(SaveField) says why.

Every set and read names a SaveField<T> the schema was built with, so a value of the wrong type does not compile and a field of another schema throws a LunySaveException where it is used. A save copies the values when it is accepted, so changing the document afterwards changes nothing it stores.
