LunyScript API Reference

Namespace CodeSmile.LunyCloud

Classes

CloudAccount

The account part of a CloudClient: explicit sign-in, sign-out and account delete, and the account state. Each call returns a request that waits until every request before it ended, and that every request made after it waits for.

CloudCalls

Calls that were already complete when they were made: what a backend returns when it did its work inside the call, as FileCloudBackend does. The client observes the outcome at its next poll, so a caller sees the same order of events it sees against a service.

CloudClient

One game's client of the cloud services: the account, player and game data, player files and leaderboards, reached through Account, Data, Files and Leaderboards. Every call returns a CloudRequest at once; Tick(), called once per frame on the main thread, sends each request in its turn, polls the backends, and ends each request with a classified outcome. No caller ever sees a task or an exception for a service outcome.

CloudData

The data part of a CloudClient: one JSON value per key in the player's data, which the client reads and writes, and the game's published data, which it only reads.

CloudFiles

The file part of a CloudClient: player files, and the C# sources registered by name that produce a save's bytes and receive a load's. A LunyScript script names a registered file and never holds bytes (C20 B); C# may also pass bytes directly.

CloudJournal

The client's last events in a fixed ring, oldest first: what an agent or a test reads to see what the client did, in order, without a debugger. Recording an event copies a struct into a slot and allocates nothing.

CloudKeys

The rule every key, file name, game data collection and leaderboard id follows: 1 to 255 characters, each a letter A-Z or a-z, a digit, _ or -. Unity Cloud Save refuses other keys with HTTP 400, so the client checks the rule once for every backend and fails such a request as Denied without calling one; the file backend then refuses what the service refuses.

CloudLeaderboards

The leaderboard part of a CloudClient: board declarations, the durable score queue, and the reads of a page, one entry and the past seasons.

CloudRequest

One request a CloudClient carries out: what it asks, where, where it is, and how it ended. Made by the client's services, never by a caller; read it after each Tick(), or set an Observer to be told when it ends.

CloudServices

The backends a CloudClient talks to, one per service. A service with no backend fails its requests as Unknown with one logged error naming what to install, so a game that uses Cloud Save without leaderboards names no leaderboard backend.

FileCloudBackend

The file backend: accounts, player data, game data, player files and leaderboards kept in five kinds of JSON file under one directory. A first-class part of the product, not a test fixture (AGENTS.md rule 52): it is how every branch is reached without a network, and what makes the automated suite run with no credentials.

LeaderboardRow

One entry of a leaderboard as a read returned it. Immutable.

LeaderboardRows

The rows of one page of a leaderboard's entries in rank order, as a read returned them, and the board's total. Immutable.

LeaderboardSeasons

A leaderboard's past seasons, as a read returned them. A board that never reset has none. Immutable.

LeaderboardSpec

A leaderboard as the game declares it: the service's board id, the update rule and the sort order configured on the dashboard (C23 A). Immutable.

LunyCloudException

A mistake in the C# that uses LunyCloud, raised where it was made: a null argument, a write to game data, which is read only to the client, a second set of services after signing in started, a leaderboard declared twice with different rules, or a completed call created as failed with no failure. The message names the call and what to change. A service outcome, such as a failed upload, is never an exception: it is a CloudRequest whose State is Failed.

MemoryCloudQueueStore

A queue store that keeps the text in memory: the queue lasts as long as this object.

SystemCloudClock

The clock a client uses when none is named: the system's UTC time and a stopwatch.

Structs

CloudAddress

A typed place a request reads or writes: a key in the player's data, an item of the game's published data, a player file or a leaderboard. Requests for one address run one at a time in the order they were made; requests for different addresses do not wait for each other. Keys are case sensitive.

CloudJournalEntry

One event of the client, as the journal keeps it. Holds references the client already held, so recording one allocates nothing.

LeaderboardSeason

One past season of a leaderboard: a version a reset archived, with the moment it started and ended.

Interfaces

ICloudAccountBackend

The account service a backend provides: signing in, signing out and deleting the account. The client calls it on the main thread, one call at a time, and never while a data or leaderboard call is in flight for a sign-out or a delete.

ICloudCall

One backend call in flight, which the client polls once per Tick() and never awaits. A backend wraps whatever its service hands back, a task or a callback, behind this interface; a backend that did its work inside the call returns a completed one from CloudCalls.

ICloudCall<TResult>

A call whose success carries a result: a JSON value, a file's bytes, a page of entries.

ICloudClock

The two times the client reads: the device's UTC time, which a queued score records as the moment of its Submit (C24 A compares it with a season's end), and a monotonic count of seconds, which spaces the score queue's retries. The domain's seam over System.DateTime.UtcNow and System.Diagnostics.Stopwatch; AGENTS.md section 4.

ICloudDataBackend

The data service a backend provides: JSON values under player data keys, read-only game data items, and player files. Every address the client passes has a key that follows CloudKeys, and every call is made on the main thread for a signed-in account.

ICloudFileSource

The C# that produces and consumes the bytes of named player files, registered with Register(string, ICloudFileSource). A script names the file and never holds its bytes, by the captain's rule "bytes are low-level constructs" (C20 B).

ICloudLog

Where the client writes its log lines. The domain names no engine type, so the LunyScript adapter writes them through LunyScriptLog in its Cloud area and the Unity host through UnityEngine.Debug. Lines are composed only at state changes and failures, never per frame.

ICloudQueueStore

Where the score queue keeps its waiting scores between sessions, so "a Submit that cannot be sent waits in a bounded queue on the device, survives a restart, and is sent later for the same account" (2026-09-09). The client reads it once when it is named and writes the whole queue, a few hundred bytes of JSON, at each change; never per frame.

ICloudRequestObserver

Told about one CloudRequest: asked whether to send it at the moment it would be sent, and told when it ended. Both calls happen inside Tick(), on the main thread, so a caller reacts to an outcome in the same frame the client observed it. Set with Observer.

ICloudText

The JSON text a save sends, read when the request is sent rather than when it is made. A caller that captured values when its save was made and encodes them only at sending, as the LunyScript adapter does, implements this, so a save that waits behind another can take later values without a new text per frame.

ILeaderboardBackend

The leaderboard service a backend provides: sending a score, reading a page of entries, one account's entry, and a board's past seasons. The client calls it on the main thread for a signed-in account; the score queue sends one score at a time.

Enums

AccountState

Where the client's account is.

CloudAddressKind

Which kind of place a CloudAddress names.

CloudCommit

What a write request did on the service, the commit-status receipt of the settled answer C09 A: a failure keeps its classification, and this says whether the service may already hold the write.

CloudFailure

Why a cloud request failed, classified once by the client or the backend that answered, so no caller ever sees an exception type for a service outcome. The LunyScript adapter maps each value to the OperationFailure of the same name.

CloudJournalEvent

What a CloudJournalEntry records.

CloudLogLevel

How serious a ICloudLog line is.

CloudRequestKind

What a CloudRequest asks a service to do.

CloudRequestState

Where a CloudRequest is: waiting its turn, sent to a backend, or ended.

LeaderboardKeeps

Which score a leaderboard keeps for an account when the account submits again: the update rule configured on the service's dashboard. The client cannot read that configuration, so the game declares it; the file backend applies it and the journal names it.

LeaderboardRanks

The order a leaderboard ranks its entries in: the sort order configured on the service's dashboard.
