The On surface inside Build(): registers blocks against the events the runner raises.

public readonly struct OnFactory
Expand Details ...

Examples

On.Ready(health.Set(100.0));
On.Update(If(health > 0.0).Then(health.Add(-1.0)));

Remarks

The params array is a build-time allocation and is inside the boundary the allocation rule permits; AGENTS.md rule 33 forbids params on the run-time path, which this is not.

No event registration here captures the authored line, and that is a language limit rather than an oversight. C# allows no parameter after a params array, so [CallerFilePath] cannot be added without taking the params sugar away from every call site. The blocks passed in carry their own locations, because the factories that built them are not params methods; see SourceLocation.

CollisionEnter(params Block[])

Registers blocks that run when this object's collider begins touching another collider.

public void CollisionEnter(params Block[] blocks)

Parameters

Type Name Description
Block[]
blocks

The blocks, in order.

Examples

On.CollisionEnter(Score.Add(1.0));

Remarks

Unity raises OnCollisionEnter on the object the script is on, so this is On. rather than When.. A script that does not call this, or CollisionStay(params Block[]), CollisionExit(params Block[]), TriggerEnter(params Block[]), TriggerStay(params Block[]) or TriggerExit(params Block[]), is not subscribed to physics callbacks at all.

The blocks run against this object. Other is the other collider, the same surface on all six contact events. Unity still allocates the Collision argument it passes into its own callback; LunyScript copies primitives from the other collider and does not store that argument.

A Pausable script that Time.Pause() has stopped still runs these blocks, the way Unity sends a collision to a MonoBehaviour that is not updating, so On.CollisionEnter(Time.Resume()) can resume the game. The project setting "Time.Pause pauses contact events" in Edit, Project Settings, LunyScript makes a pause skip them on a Pausable script, as it skips On.Update. A script whose component is disabled runs none of the six. Time.Pause() also stops Unity's fixed step, so a paused game meets a contact only when it steps physics itself.

Exceptions

LunyScriptUsageException

blocks is null or contains null.

Despawned(params Block[])

Registers blocks that run once when the incarnation ends, while the instance and its object are still valid.

public void Despawned(params Block[] blocks)

Parameters

Type Name Description
Block[]
blocks

The blocks, in order.

Examples

On.Despawned(Object.Destroy("Shield"));

Remarks

This is the bounded cleanup the settled contract-dispatch-order answer asks for before the incarnation is invalidated: the instance is still in the runner's live list, its host is still alive, and the objects it created still exist, so these blocks can act on all three. The objects it created are destroyed after they have run.

It is not delivered for an instance the scene-unload sweep collects, because that sweep exists for a host that went away without telling LunyScript and these blocks would run against a destroyed object; docs/host-transform-cache.md.

Enabled(params Block[])

Registers blocks that run when the instance becomes enabled, having been disabled.

public void Enabled(params Block[] blocks)

Parameters

Type Name Description
Block[]
blocks

The blocks, in order.

Examples

On.Enabled(Armed.Set(true));

Remarks

Delivered once per transition: enabling an already-enabled instance delivers nothing. An authored Object.Activate() produces it, and so does Unity's own OnEnable on a managed object, through LunyScriptBehaviour - including the first activation, which is where Unity delivers OnEnable for the first time. It therefore runs before On.Ready on a managed object, the way OnEnable runs before Start.

A bare ScriptRunner.Spawn, which a test uses and a managed object does not, delivers none: it writes the enabled state rather than changing it.

Exceptions

LunyScriptUsageException

blocks is null or contains null.

Remarks

Unity runs the fixed step zero to many times per frame, before Update; a rigidbody move belongs here rather than in Update(params Block[]). AGENTS.md rule 54 and 56.

On.Ready still runs before this instance's first fixed step, the same way it runs before its first frame update. The watches do not run here: they are polled once per frame, after Update(params Block[]).

Request(Request, params Block[])

Registers one section of a request this script accepts. Another script sends the request with Request(target, ThisScript.Requests.Name); the sections of one request run in the order they were written, as one invocation, inside the sender's block.

public void Request(Request request, params Block[] blocks)

Parameters

Type Name Description
Request
request

A request this script declared with Define.Request().
Block[]
blocks

The blocks, in order.

Examples

Heal = Define.Request();
On.Request(Heal, If(Health >= 100).Then(Reject()));
On.Request(Heal, Health.Add(25));

Remarks

Sender inside the blocks is the script that sent the request. Reject() refuses it: the sections after the current one do not run, and what already ran stays done. A script handles only its own requests. docs/proposals/script-communication.md is the contract.

This takes a params array, so it captures no authored line; AGENTS.md rule 72.

Exceptions

LunyScriptUsageException

The request was never declared, has no name yet, or is another script's; or blocks is null or contains null.

Spawned(params Block[])

Registers blocks that run at the start of every incarnation: after Created(params Block[]) on the first, and again each time a pool hands the object out.

public void Spawned(params Block[] blocks)

Parameters

Type Name Description
Block[]
blocks

The blocks, in order.

Examples

On.Spawned(Body.MakeDynamic(), Particles.Play());

Remarks

Delivered once per incarnation, after declared inputs are resolved and after the placement a pool spawn names has been written, and before On.Enabled and Ready(params Block[]). A pooled object keeps whatever native state its previous use left, so this is where a script resets what its object needs for the next use: a Rigidbody's velocity, an animation, a particle effect. LunyScript resets the script's own variables and nothing native.

Exceptions

LunyScriptUsageException

blocks is null or contains null.
