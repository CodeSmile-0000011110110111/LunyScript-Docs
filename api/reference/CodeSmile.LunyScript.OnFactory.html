Struct OnFactory

Namespace
CodeSmile.LunyScript
Assembly
ApiSource.dll

The On surface inside Build(): registers blocks against the events the runner raises.

public readonly struct OnFactory

Examples

On.Ready(health.Set(100.0));
On.FrameUpdate(If(health > 0.0).Then(health.Add(-1.0)));

Remarks

The params array is a build-time allocation and is inside the boundary the allocation rule permits; AGENTS.md rule 33 forbids params on the run-time path, which this is not.

No event registration here captures the authored line, and that is a language limit rather than an oversight. C# allows no parameter after a params array, so [CallerFilePath] cannot be added without taking the params sugar away from every call site. The blocks passed in carry their own locations, because the factories that built them are not params methods; see SourceLocation.

CollisionEnter(params Block[])

Registers blocks that run when this object's collider begins touching another collider.

public void CollisionEnter(params Block[] blocks)

Parameters

blocks Block[]

The blocks, in order.

Examples

On.CollisionEnter(Score.Add(1.0));

Remarks

Unity raises OnCollisionEnter on the object the script is on, so this is On. rather than When.. A script that does not call this, or CollisionStay(params Block[]), CollisionExit(params Block[]), TriggerEnter(params Block[]), TriggerStay(params Block[]) or TriggerExit(params Block[]), is not subscribed to physics callbacks at all.

The blocks run against this object. Other is the other collider, the same surface on all six contact events. Unity still allocates the Collision argument it passes into its own callback; LunyScript copies primitives from the other collider and does not store that argument. Contact events are process events: a Pausable script does not run these blocks while the runner is paused.

Exceptions

LunyScriptUsageException

blocks is null or contains null.

Created(params Block[])

Parameters

The blocks, in order.

Examples

Remarks

Delivered after declared inputs are resolved and before Ready(params Block[]). A pooled respawn onto the same host does not raise it again; a bind to a different host does. It does not promise Unity's Awake timing: a host that is already in the scene still gets it on first bind.

Despawned(params Block[])

Registers blocks that run once when the incarnation ends, while the instance and its object are still valid.

public void Despawned(params Block[] blocks)

Parameters

blocks Block[]

The blocks, in order.

Examples

On.Despawned(Object.Despawn("Shield"));

Remarks

This is the bounded cleanup the settled contract-dispatch-order answer asks for before the incarnation is invalidated: the instance is still in the runner's live list, its host is still alive, and the objects it created still exist, so these blocks can act on all three. The objects it created are destroyed after they have run.

It is not delivered for an instance the scene-unload sweep collects, because that sweep exists for a host that went away without telling LunyScript and these blocks would run against a destroyed object; docs/host-transform-cache.md.

Exceptions

LunyScriptUsageException

blocks is null or contains null.

Enabled(params Block[])

Registers blocks that run when the instance becomes enabled, having been disabled.

public void Enabled(params Block[] blocks)

Parameters

blocks Block[]

The blocks, in order.

Examples

On.Enabled(Armed.Set(true));

Remarks

Delivered once per transition: enabling an already-enabled instance delivers nothing. An authored Object.Activate() produces it, and so does Unity's own OnEnable on a managed object, through LunyScriptBehaviour - including the first activation, which is where Unity delivers OnEnable for the first time. It therefore runs before On.Ready on a managed object, the way OnEnable runs before Start.

A bare ScriptRunner.Spawn, which a test uses and a managed object does not, delivers none: it writes the enabled state rather than changing it.

Exceptions

LunyScriptUsageException

blocks is null or contains null.

FixedUpdate(params Block[])

Registers blocks that run once per fixed step, for as long as the instance is enabled.

public void FixedUpdate(params Block[] blocks)

Parameters

blocks Block[]

The blocks, in order.

Examples

On.FixedUpdate(Speed.Add(-0.02));

Remarks

Unity runs the fixed step zero to many times per frame, before Update; a rigidbody move belongs here rather than in FrameUpdate(params Block[]). AGENTS.md rule 54 and 56.

On.Ready still runs before this instance's first fixed step, the same way it runs before its first frame update. The watches do not run here: they are polled once per frame, after FrameUpdate(params Block[]).

Exceptions

LunyScriptUsageException

blocks is null or contains null.

Message(string, params Block[])

Registers blocks that run on the peer this message is delivered to, which is the peer with authority over the object it was sent from.

public void Message(string messageName, params Block[] blocks)

Parameters

messageName string

What the message is called. Use nameof, so that a rename moves this and the matching Net.Send.ToAuthority together.

blocks Block[]

The blocks, in order.

Examples

On.Message(nameof(RequestReady), isReady.Set(true));

Remarks

Two calls naming the same message append to one list, in the order they were written, the way two FrameUpdate(params Block[]) calls do.
