Assigns one GameObject to one script type. This is the component a user adds; the script is named by an explicit field rather than by a type name written as a string.

Remarks

The name is LunyScriptBehaviour and not LunyScriptComponent because it inherits from MonoBehaviour, and Unity's own naming for that is "behaviour"; AGENTS.md rule 28.

An object is assigned to a script, not a script to an object. One ScriptProgram is built per script type and shared by every object assigned to it; what belongs to the object is its ScriptInstance, which holds the slots. AGENTS.md rule 21 and docs/execution-model.md.

The object is managed by LunyScript from here on. Calling Object.Destroy, SetActive or AddComponent on it from outside LunyScript is outside the contract, and where LunyScript observes it, it throws. AGENTS.md rule 20 states the contract in full, including what it does not promise.

Choose Script To Run in the Inspector. The selected managed reference is serialized with the scene or prefab and copied by Instantiate. The built script is held separately, so execution never writes to the serialized reference.

The assets a script declares are assigned here too, one field per declared input, below the script. That is the settled api-asset-inspector-location answer: the host Inspector is where an author assigns them, one object at a time. An input this object leaves empty resolves to the input's own declared source or to the asset placeholder for its type, and that resolution is reported.

Script

The script object to read this object's variables from. From Awake onward it is the object LunyScript built for this object's script type, which is the one object of that type whose variable properties were assigned. Before Awake it is what the serialized field holds.

public Script Script { get; }

Property Value

Script

Examples

var script = (PlayerScript)behaviour.Script;
var health = behaviour.GetNumber(script.Health);

Remarks

After Awake, this is reference-equal to the serialized object only if that object is the program's BuiltScript. A later prototype of the same script type is replaced by that built object. docs/slice-decisions.md D4.42.

A component with a negative DefaultExecutionOrder must not cache this in its own Awake, because that Awake runs before this component's and would cache the un-built object. Read it at use time instead; NetMatchBinding in the netcode demonstration is the worked example.
