Class InstanceLayout

How many slots of each kind one instance of a program owns, and what value each slot starts from. Built once per script type and never changed afterwards.

public sealed class InstanceLayout
Inheritance
object
InstanceLayout

Examples

var layout = program.Layout;
// one Double and one Boolean: 8 + 8 = 16 payload bytes in 2 arrays

Remarks

The layout is what makes a spawn's cost predictable: it names every array a ScriptInstance allocates and how many bytes of payload each one carries, so the allocation test can assert an exact figure rather than a ceiling. See AGENTS.md rule 31, boundary 1, and docs/execution-model.md.

Byte counts here are payload only. A managed array also carries a header whose size differs between Mono and CoreCLR, so the layout deliberately does not include it; the allocation test measures the header on the runtime it is running on and adds SlotArrayCount of them. A header size baked in here would be right on one runtime and wrong on another.

Remarks

An owned-object slot holds a reference rather than a value, so its payload is IntPtr.Size bytes and not a fixed number written here: a 64-bit player and a 32-bit Web build disagree, and a constant baked in would be right on one and wrong on the other, which is the mistake the array-header remarks on this type describe.

SlotArrayCount

Number of arrays a spawn allocates. An empty slot kind costs no allocation, because the instance uses Array.Empty for it, so this is the count of kinds a program actually uses rather than the number of kinds that exist.

SlotBytes

Payload bytes every instance's slot arrays hold together, with each array's payload rounded up to the next multiple of 8 because that is how a managed array is padded. Excludes array headers and the instance object itself; see the remarks on this type for why.
