The plain C# spawn director of one scene: it runs any number of recipes, each a separately owned run with its own seed, phases, groups and objects (the captain's Q12 answer), shares one live population limit and one attempt budget between them, and asks its ISpawnWorld to place and release objects. A Unity SpawnHost owns one per scene and advances it by game time; a test advances it by hand.

Examples

var session = new SpawnSession(world, new SpawnSessionOptions(populationLimit: 100));
var run = session.Start(recipe, seed: 7);
session.Advance(1.0 / 60.0);                 // the run enters its first phase and admits its due members
Console.WriteLine(run.Read().Live);

Remarks

One boundary per Advance(double). Every command made since the last boundary is applied first, in call order: starts, ended uses, latched signals, participant changes and cancellations. Then, for each run, a stop signal or a source group's end stops its groups, a cancellation ends the run, a latched failure signal or a required member's passed deadline fails it, and only then can its phase succeed, at most one transition per boundary (the captain's Q40 answer: failure before success). Last, due members are admitted in round-robin turns over runs and groups under the attempt budget (Q30: work delayed by the budget stays visible and can expire under its deadline). A terminal run admits nothing more.

Absence is completion. Any end of a member's use clears it (the captain's Q29 answer); only a Combat defeat counts as clear-speed evidence (Q46).

Steady state allocates nothing. Starting a run allocates its group and cohort state; admitting, ending, signalling and reading reuse arrays sized when the run started or the population first grew.

Methods

Advance(double)

Runs one boundary after seconds of game time: applies every queued command, ends runs by cancellation, failure or success in that order, and admits due members under the attempt budget. A paused game advances by 0 or not at all, which freezes every schedule and deadline (the captain's Q30 answer).

public void Advance(double seconds)

seconds

End()

Ends the session: every run that has not ended is cancelled with SessionEnded, every live object is released and every handle becomes stale. A second call does nothing.
