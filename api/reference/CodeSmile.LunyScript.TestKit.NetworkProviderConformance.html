Remarks

Why this exists. LunyScript ships two providers - FakeNetworkProvider, which AGENTS.md rule 52 makes a first-class part of the product, and NgoNetworkProvider - and three separate review rounds each found one send path where they disagreed about what a peer without a session is. Each was fixed on its own, which closed three instances and not the class. A double that can drift from the real implementation silently is the defect underneath all three, and one shared list of assertions run against both is what removes it.

It returns text rather than asserting. The test kit ships in the product and does not reference NUnit; a caller in a test assembly asserts the returned list is empty and gets every divergence in one message rather than the first. A user who writes their own provider can run it the same way.

What it deliberately does not cover, and how far each provider is actually taken. The connected half of the contract needs a session, and standing one up differs so much between the two providers - a paired in-process peer against two NetworkManagers and a transport - that the setup could not be shared without describing one of them wrongly. So this covers the sender's own guard: what a provider with no session reports, and that its three send paths deliver nothing. The caller supplies the receiving peer, and only the in-process provider has one to supply without a live session, so the delivery half of this list is exercised on that provider alone; against the real backend it checks the reported state and that a send with no session neither throws nor fills that provider's own queues.

The mirror case is a separate test. A CONNECTED provider sending to a peer that has not joined is refused by a different guard, and no offline-sender list can reach it; NetcodeTests.AConnectedPeerSendingToAPeerThatHasNotJoined_DeliversNothing is where that half lives. Between the two, each of the six guards on the in-process provider's three send paths has a test that fails when it is removed.

Remarks

Calls the three send paths as well as reading the state. A send made with no session must do nothing and must not throw: the gateway already refuses to call one, so a provider that threw here would turn a caller's ordering mistake into a crash rather than a no-op, and a provider that delivered would hand the other peer a value no real session carried.

Pass the peer wherever one exists. Every send path delivers into the OTHER provider's queues, so draining only the sender observes nothing at all and this list would report no divergence with every send guard removed. The peer must be in a session, so that the only thing left refusing the send is the sender's own guard, which is what this is checking.
