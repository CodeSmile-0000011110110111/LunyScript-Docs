Class LunyScriptNetworkBehaviour

Binds the script instance on this object to the object's network identity, so that its synchronised variables and its messages reach the same object on every peer.

[RequireComponent(typeof(LunyScriptBehaviour))]
[AddComponentMenu("LunyScript/LunyScript Network Behaviour")]
public sealed class LunyScriptNetworkBehaviour : NetworkBehaviour

Remarks

This is the whole bridge between Netcode for GameObjects and the LunyScript core. It translates one fact, the network object id, and does nothing else: no state is copied here, no value is serialised here, and the core is told nothing about NGO. AGENTS.md rule 49.

The object needs a NetworkObject, a LunyScriptBehaviour that has already been given a script, and this component. The order that matters is that the script is named before LunyScriptBehaviour.Awake runs, which is what spawns the instance. The demo prefab carries its assignment in Script To Run.

Despawn unbinds. An id that outlived its object would make an arriving message reach an instance that is no longer the object it names, so the binding ends where the spawn ends rather than where the GameObject is destroyed.

Remarks

NGO-ASSUMPTION: NetworkObjectId is a UInt64 that NGO assigns from a counter starting at 1 and increasing, so the value fits an Int32 for any session this product can produce. The narrowing is stated here rather than hidden; a session that spawned more than two billion objects would need INetworkProvider's object id to widen, and the MaxObjectId check below is what would report that rather than silently binding to a wrong id.
