Remarks

An unassigned binding must not enter execution as a null reference. That is the settled requirement; the placeholder is chosen to be recognisable and to change no gameplay outcome, and using one is always reported so that a placeholder never hides the missing assignment. Where no placeholder can be both recognisable and harmless, the type gets none and the binding fails instead.

This is not Unity's Preset feature. A Unity Preset stores Inspector settings and applies them to filtered assets; an asset placeholder is the object a declared [Asset] input resolves to when no assigned asset is available.

A placeholder is built the first time a type actually needs one, and then kept. A scene in which every input is assigned builds none of them, which is why the built-in registrations are factories rather than objects.

This is mutable static state, and it carries the attribute that resets it. AGENTS.md rule 17 forbids one and rule 18 names [AutoStaticsCleanup] as the mechanism for the unavoidable case: with domain reload disabled a static keeps its value from the previous Play session, and a placeholder built in that session is a destroyed object by the time the next one reads it. The type is partial because Unity's code generator emits a second partial declaration holding the generated reset method. A registration a package makes in code is re-applied after that reset the way it was applied the first time, from a startup callback.

The project settings asset the accepted design names as the second configuration source is not implemented yet; AssetPlaceholderSource is where it joins, and every diagnostic already names the source it came from.
