What one allocation measurement observed, and with which instrument. Carries the instrument because the two instruments this project has are not both available on every runtime, and a figure recorded without naming its instrument cannot be compared with another run's. Where an allocation was observed, Instrument names the instruments that observed it rather than every instrument that was usable.

Property Value

Remarks

True when any usable instrument reported an allocation, not when one chosen instrument did. Where both work they are both consulted, because either can miss what the other catches: the byte counter returns a constant on Unity 6.7's Mono, and a per-iteration byte average rounds a rare allocation away while the profiler still counts its event.

BytesPerIteration

Managed bytes allocated per iteration, or -1 when the byte counter is not usable on this runtime.

public long BytesPerIteration { get; }

Property Value

long

Remarks

This is an average and a zero here does not mean the work allocated nothing. It is TotalBytes divided by MeasuredIterations in integer arithmetic, so work that allocates 32 bytes once across 128 iterations reports 0 while TotalBytes reports 32. It is exact only when every iteration allocated the same number of bytes. Assert on Allocates, or on TotalBytes, to ask whether anything was allocated; use this figure only for a per-iteration size that the same test has already established is uniform, such as one spawn's cost.

EventsPerIteration

Allocation events per iteration, or -1 when the profiler recorder is not usable on this runtime. Integer division, so it carries the same caution as BytesPerIteration: it is exact only when every iteration allocated the same number of times, which is what an allocation test asserts.

public int EventsPerIteration { get; }

Instrument

Names the instrument or instruments that observed an allocation in this sample, and where none did, names the instruments that were usable, for the log line and for the failure message.

public string Instrument { get; }

Property Value

string

Examples

On a runtime where only the profiler works and the measured work allocated, this reads "profiler"; where the same work allocated nothing, it reads "none observed, usable: profiler only".

Remarks

A sample whose Allocates is true reports only the instruments whose own figure is above zero, so a verdict that came from the profiler alone is not attributed to a byte counter that reported nothing. A sample whose Allocates is false reports "none observed, usable: " followed by the usable instruments, which is what keeps a measured zero distinguishable from a runtime where the question could not be asked. ObservingInstruments(long, int) produces the string.

MeasuredIterations

How many iterations AllocationEvents covers. A test that expects a known number of allocations per iteration needs this to turn the total into a per-iteration figure.

public int MeasuredIterations { get; }

Property Value

int

TotalBytes

Managed bytes allocated across all measured iterations, as the byte counter reported them, or -1 when the byte counter is not usable on this runtime. Zero and -1 mean different things and must not be conflated.

public long TotalBytes { get; }

Property Value

long

Remarks

This is the figure the instrument produced, undivided. BytesPerIteration divides it and can therefore lose an allocation that happens on some iterations and not others; this one cannot.
