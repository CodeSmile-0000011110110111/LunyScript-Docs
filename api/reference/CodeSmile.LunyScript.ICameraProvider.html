Interface ICameraProvider

Namespace
CodeSmile.LunyScript
Assembly
ApiSource.dll

What a camera backend provides to the CameraGateway: choosing which rig a view renders, sizing that view, and writing a rig's tracking targets. Script code never sees this type; it sees the View and Camera surfaces.

public interface ICameraProvider
Expand Details ...

Examples

runner.CameraGateway.UseProvider(new FakeCameraProvider());

Remarks

The shipped backend is Cinemachine and only Cinemachine. The captain's answer on the camera family, 2026-09-13, is that "camera should be strictly routed through and dependent on cinemachine", so CinemachineCameraProvider in CodeSmile.LunyScript.Cinemachine is the one real implementation and it is the only place in the product that names that package. FakeCameraProvider is a second real implementation that records what it was asked to do, which is what makes every camera block testable in Edit Mode with no package and no scene.

Every object here is a UnityEngine.Object the author assigned. The core cannot name a Cinemachine type or a Camera, so a view and a rig reach the provider as the object a declared asset input resolved to, and the provider is what knows whether that object is one. An object that is not produces NotAView or NotACameraRig and nothing is written.
