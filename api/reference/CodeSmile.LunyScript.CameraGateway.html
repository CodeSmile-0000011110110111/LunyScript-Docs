The core's one entry point to the camera. Owns the ICameraProvider, passes each authored operation to it, and reports a refused one once.

Remarks

This is the camera counterpart of NetworkGateway and InputGateway and is the same shape for the same reason: the core may not reference Cinemachine, so the core owns an interface and a separate, package-gated assembly implements it.

With no provider installed, a camera block writes nothing and says so once. That is what the accepted design asks of an absent optional adapter: a diagnostic, and no block executes. A project without the Cinemachine package therefore still builds, still runs and still passes its tests; the camera operations do nothing and the reason is in the Console.

A refusal is reported once per operation per object pair. These operations are normally authored in On.Ready, but nothing stops one appearing in On.FrameUpdate, and a Console line per frame would bury the one that matters. The bookkeeping allocates only on the failure path, which is not the steady state.
