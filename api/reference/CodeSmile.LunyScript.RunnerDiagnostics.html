Native diagnostics for one explicitly supplied local runner. Reads execute no authored logic.

public sealed class RunnerDiagnostics

Examples

var current = runner.Diagnostics.ReadCurrent(runner.Diagnostics.GetIdentity(instance));

Remarks

Caller-owned snapshots allocate only on explicit observation. Current-only Shallow coverage is the default: in the Editor every instance records each block's last outcome, which a snapshot carries in NodeOutcomes. BeginTrace explicitly collects ordered action records; current snapshots do not contain historical values or a condition preview. In the Editor every instance also records which script, object and block last changed each variable, which a snapshot carries in ValueWrites, and breakpoints set with SubmitBlockBreakpoint(DiagnosticIdentity, int, bool, bool, int) and SubmitValueBreakpoint(DiagnosticIdentity, int, bool, bool, int) pause Play Mode. Service work before a runtime provider is ready retains the existing gateway queue contract. Of the commands, only an applied SubmitFireBlock(DiagnosticIdentity, int, bool, int) runs an authored block.

Remarks

Once applied, each time the block starts to run in this lifetime the runner records a pause and, when the dispatch it runs in has completed, asks the installed pause to pause the application: in the Editor, Play Mode pauses at the end of that frame, after every script the frame runs. The block and everything after it still run. A breakpoint lasts until it is cleared or the lifetime or the session ends; a pooled respawn starts with none. A block object placed twice breaks in both places, under its OutcomeNode. A condition or a value node has no block and is refused, and so is a runner with no pause installed, which is every runner outside the Editor's debugger.

Remarks

Apply(DiagnosticCommand) runs the block at an idle boundary, as a dispatch of its own through the runner's per-action containment, then applies the object lifetime requests it made, records an intervention and, when the block threw, stops the instance as any failed block does. A node whose FireUnavailableReason is not null is refused with that reason. A faulted or disabled instance, a networked instance this peer has no write authority over, and a player built without DEBUG or LUNYSCRIPT_TRACE are refused too. Firing an If runs its condition, or its forced branch, and that branch; firing a watch runs its check once.

An If object placed twice is forced in both places, under its OutcomeNode. Forcing an already forced If replaces its branch.

Remarks

Once applied, each time the variable's value changes the runner records a pause naming the script, object and block that changed it, and pauses the application the way SubmitBlockBreakpoint(DiagnosticIdentity, int, bool, bool, int) describes. A write that stores the value already held is no change, and a debugger value edit does not pause. A shared variable breaks on a change any script makes to its store, so the pause can name another script on another object. Internal storage is refused, and so is a lifetime that records no value changes, which is every lifetime outside the Editor.
