Enum TransformSpace

Which frame a transform verb's numbers are in.

public enum TransformSpace

Fields

Local = 1

The object's own oriented axes for a displacement, and the parent's frame for an absolute value. The default for MoveBy and RotateBy.

World = 0

The scene's frame.

Examples

host.ReadTransform(TransformRelation.Self, 0, TransformSpace.Local, TransformPart.Position, out var x, out var y, out var z);

Remarks

Local names two different frames, and which one it is depends on the verb. That is deliberate and it is the captain's answer to API-semantics row T02 on 2026-09-13, which is also what the previous version of LunyScript did; docs/verification/transform-space-spelling.md is the reading of it.

  • For a displacement - MoveBy and RotateBy - Local is the object's own oriented axes, which is Unity's Space.Self. A move of one unit along X goes one world unit along the direction the object faces, unaffected by its own or its parent's scale; a turn composes after the rotation the object already has.
  • For an absolute value - a read or a set of a position, a rotation or a scale - Local is the parent's frame, which is Unity's localPosition, localEulerAngles and localScale.
World is the scene's frame for both, and for a turn it composes before the rotation the object already has.

An object at the scene root with no rotation of its own cannot tell the two apart, which is why a test that separates them gives the object both; AGENTS.md rule 56 names that as the plausible-looking wrong result.
