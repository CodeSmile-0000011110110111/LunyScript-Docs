Class CameraHost

Namespace
CodeSmile.Luny.Camera.Unity

ApiSource.dll

The one persistent owner of the views LunyCamera creates: it moves to DontDestroyOnLoad, creates each view from an Inspector-assigned template, a Unity Camera with a CinemachineBrain and the Cinemachine cameras it shows, keeps those views and their identities across scene loads, binds outputs another owner keeps, and destroys what it created when it is disabled or destroyed. A second CameraHost waking while one exists is a configuration error and throws.

Remarks

Templates. The personal template is what CreateView(ViewAudience) instantiates, one per player; the shared template is the host's SharedView, created when the host starts. Each created view gets an output channel of its own, from Channel01 up, written to its brain and to every Cinemachine camera of its template, so four brains show four rigs at once. A scene brain that listens to every channel would render those rigs too; the host warns once per such brain.

Scene loads. A created view keeps its Id. A bound output that a scene unload destroyed reads unavailable, and so does a follow or look-at target the scene held; the host logs one warning for each. Assign this host to a CoopHost and the session creates each participant's view from the personal template, points it at their pawn, frames every local pawn in the shared view and lays the views out.
