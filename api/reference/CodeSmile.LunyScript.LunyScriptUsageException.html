Remarks

Every message names the mistake and the supported alternative, because this exception is read by a user of the product rather than by a maintainer of it. Most of these are raised at build time, which runs once per script type at launch, so a script that can throw one of those throws it on the first run.

Seven cases are raised at run time instead, and two of them can fire long after launch.

  • The implicit conversion of a condition block to bool, AGENTS.md rule 38, which throws in release builds too when a C# if or while tests the block.
  • The text-capacity check in ScriptInstance.SetText, reached from SetTextBlock and CopyTextBlock. Build time checks only the 509-byte literal limit and does not know the target variable's TextCapacity, so a 37-byte literal written into a TextCapacity.Bytes32 variable (29 usable bytes) builds clean and throws on the first frame that block executes, which may be long after launch if it sits behind an If.
  • The slot-range check in ScriptInstance, reached from GetNumber, SetNumber, GetFlag, SetFlag and every text accessor. A Var<T> handle carries a slot index and a kind and nothing that identifies its program, so a handle declared by a different script type addresses this script's slot of the same index; where that index is past the end of this instance's array for its kind, the access throws and the message names that cause. It fires on the first frame the block executes, which may be long after launch. docs/slice-decisions.md entries D4.31 and D4.32 record the accepted edge and the shape of the check.
  • ScriptRunner.RaiseReady called twice for one spawn.
  • An invalid Script type selected for serialization.
  • A C# read or Send on LunyScriptBehaviour after the object is destroyed, or before Awake. The message names the object and the call.
  • Other evaluated outside a contact event. The block is built in Build() and runs later, so a read in On.FrameUpdate throws when that event runs. The message names the call and the six contact events that may use it.

This derives from LunyScriptException and no longer from InvalidOperationException. That base is the one interception point a debugger filter or a diagnostic layer uses to select everything LunyScript threw; docs/api-changes.md records the change and why the .NET type was not kept.
