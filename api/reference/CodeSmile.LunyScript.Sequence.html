A named sequence: several blocks a script declared as one with Define.Sequence, under the name of the property it is assigned to. It converts to a block wherever a block is accepted.

public readonly struct Sequence
Expand Details ...

Examples

DodgeRoll = Define.Sequence(Crouch.Set(true), Wait(0.2), Lane.Add(1), Wait(0.4), Crouch.Set(false));
On.Message("Dodge", Routine("Dodge").Run(DodgeRoll));

Remarks

The name comes from the property. DodgeRoll = Define.Sequence(...) in a partial script's Build() makes the generator write the DodgeRoll property, and that property's setter gives the sequence the name DodgeRoll and the line of the Define call. The debugger shows the sequence as one row with that name, folded, and a diagnostic names it the same way.

A sequence does what its blocks would do written out in its place. In an event list, a Then or another list that runs every block at once, it runs its blocks in that frame. As a step of a routine, a group, a Run body or a Choose option's action, each of its blocks finishes before the next begins, and a Wait inside it holds that owner. In a concurrent group it is one child. docs/proposals/sequences.md is the contract.

Placed a second time it is a copy, with progress of its own, the rule for every composed block. A Define.Sequence assigned to a local or to a hand-written property has no name, and using it as a block is refused; Sequence(...) is the spelling for a sequence without a name.
