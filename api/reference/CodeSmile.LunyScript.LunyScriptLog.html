Remarks

No code outside this class calls UnityEngine.Debug.Log, LogWarning, LogError or LogException. Before this class existed the prefix "LunyScript <area> | " was written out again as a string literal at every call site, in ten files, so changing the format meant editing every literal and a missed one was invisible. SourceRuleTests.NoCodeOutsideTheLoggingSurfaceCallsUnityDebugLog is what makes that a failing test rather than a convention.

Every method here carries [HideInCallstack], and that attribute is what makes a log entry open the caller's own line. Unity skips a hidden frame both when it prints the stack and when it chooses the entry's double-click target, so the first frame it accepts is the one that called this class. Deleting the attribute was measured moving that target off the caller and into Write(in LunyScriptLogRecord, Object) in this file; docs/console-navigation.md. It hides frames and cannot reveal one, which is why the authored location is carried in the record rather than looked for on the stack; see SourceLocation.

The console and runtime debugger share this structured record contract. Write(in LunyScriptLogRecord, Object) takes a LunyScriptLogRecord with the area, the script, the block and the authored location as separate fields, and formatting is the last thing that happens to it. A window that traces calls reads the record; the Console gets the string.

Logging allocates and this class does not pretend otherwise. Composing a message builds strings, which AGENTS.md rule 33 forbids on the run-time path. The product's own call sites are failure paths, build-time paths and once-per-operation paths. The one block that logs each time it runs is the author's own Debug.Log, Debug.Warn and Debug.Error, and only in a build that defines DEBUG: that write is the sixth boundary AGENTS.md rule 31 names, and a build without DEBUG compiles it out.

Remarks

The shape is LunyScript <area> | <message>, then the script and block names when the record names them, then the authored location when it has one.

A line a script's own Debug block wrote has the author's shape instead: <message> (Script: <script>, Object: <object>), then the authored location. The record's Kind is AuthoredLog. The prefix is left off because the line is the author's output, not something LunyScript is reporting.

In the Editor the location is written as a Unity rich-text hyperlink. Unity subscribes EditorGUI_OpenFileOnHyperLinkClicked to its own EditorGUI.hyperLinkClicked event for every console message, and that handler opens the href at the line attribute. Writing the authored location as such a link is therefore what makes a click open the user's own script line, per log entry and with nothing to match up afterwards. Outside the Editor the same location is written as plain text, because a player log and a gate log are read as text and the markup would be noise there.

Remarks

Forwards the original exception to UnityEngine.Debug.LogException and retains its structured context for the LunyScript console in the Editor. A LunyScriptException presents the authored location as the topmost frame of that stack, so the entry prints the user's own line first.

A double-click on that entry opens the line that called this method, not the authored line. Unity chooses a Console entry's target from the live call stack when the entry is written, and [HideInCallstack] skips this method's own frame but cannot reach a frame that has already unwound. The authored location reaches the user through the entry's printed text. docs/console-navigation.md holds the measurement.
