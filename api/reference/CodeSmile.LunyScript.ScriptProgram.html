Class ScriptProgram

One script type, built. Holds the immutable block tree, the On.* event table and the instance layout, and is shared by every object running that script.

public sealed class ScriptProgram
Expand Details ...
Inheritance
object
ScriptProgram

Examples

var program = runner.GetOrBuildProgram(new PlayerScript());
var instance = runner.Spawn(program, host);

Remarks

A program is built once per script type, not once per object. The predecessor called Build() once per object, at roughly ninety managed allocations per spawn, which made it unusable for a game that spawns enemies and pickups. AGENTS.md rule 21; docs/execution-model.md has the whole model.

Nothing on a program is mutable. Per-object state lives in slots on a ScriptInstance, and running the same block against a different instance is all that "swapping the context" means.

Remarks

FindVariable<T>(string)

Finds a variable this script declared, by the name it was declared with, and returns its handle.

public Var<T> FindVariable<T>(string name) where T : struct

Parameters

Type Name Description
string
name

The name the script declared, which nameof produced.

Returns

Var<T>

The same handle Build() assigned to the script's own property.

Type Parameters

T

Number, Flag or Text, matching how the variable was declared.

Examples

var health = program.FindVariable<Number>(nameof(PlayerScript.Health));

Remarks

This is the tooling path, not the fix for reading a variable from the wrong object. It exists so that code holding a program and a name - a runtime inspector, a debugging window, a test - can reach a variable without holding a Script object at all. Ordinary code reads the variable from BuiltScript, which Script returns. docs/slice-decisions.md D4.42 records both and which is which.

It is never read on the run-time path: a block holds the handle its build gave it. The search is a linear scan over the script's declarations, which number in the tens.

The shadow slots a When.Var(x).Changed watch and a synchronised variable add are refused rather than returned. Their names are in angle brackets and no script wrote them, so returning one would hand out a slot the caller cannot have meant.

Exceptions

LunyScriptUsageException

No variable of that name was declared, the name belongs to a slot LunyScript added rather than the script, or the variable was declared with a different kind than T.
