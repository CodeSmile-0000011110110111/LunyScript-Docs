Remarks

A user should never see one of these. If they do, it is a LunyScript defect and not something they did. Every concrete block type is internal with an internal constructor, built by the factories and never by user code, so a null argument there is the product's mistake; that is the audience split AGENTS.md rule 71 records, and it is why these do not share a type with the mistakes a user can make.

Most of these are raised through CodeSmile.LunyScript.LunyScriptContract, whose guards are compiled out when DEBUG is not defined, so those cost a release build nothing and can be met only in the Editor and in a development player. Two sites are not those, and throw this type in every build: CompletedOperation.Failed and CompletedLoadOperation.FailedLoad. A guard is allowed to be conditional only where the failure its removal gives up is loud; breaking those two makes IsSuccess true on a failed cloud call, which is a silent wrong value rather than a crash. Do not read this type as impossible in a release build.
