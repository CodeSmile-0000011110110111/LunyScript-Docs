A handle to one prefab input of a script. Returned by Bind.Prefab at build time; what the input holds is an instance read, because the value belongs to the object and not to the script type.

public readonly struct Prefab
Expand Details ...

Examples

[Asset] public Prefab Sentry { get; private set; }
On.Ready(Object.Spawn(Sentry).At(new Vec3(0.0, 1.0, 0.0)).Into("Guard"));

Remarks

This is the declared asset input of Asset<T>, narrowed to a prefab. It occupies an asset slot, it is declared in the same table, and it is resolved by the same three steps at spawn. The two differences are stated here because they are the whole reason the type exists.

A prefab input refuses a GameObject that is not a prefab. An Asset<GameObject> is satisfied by any GameObject, including one dragged out of the Hierarchy, and a scene object assigned to an input a script spawns from is a mistake that shows up as a duplicated scene object rather than as a message. A value the host assigned that is not a prefab asset is refused at spawn, and the input then resolves as if nothing had been assigned.

Object.Spawn takes this type and nothing else, so passing an Asset<AudioClip> or an Asset<GameObject> to a spawn does not compile.

The declared name is the input's durable identity, the way it is for Asset<T>: a value stored on a host is matched to an input by that name, which is why the name comes from nameof and why renaming a declared input orphans what a scene stored for the old name.

A handle is valid only inside the Build that declared it, for the reason Var<T> states: it carries a slot index and nothing that identifies its program.
