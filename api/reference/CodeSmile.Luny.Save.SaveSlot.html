One acquired document: a path in the player's data folder, the SaveSchema every document saved there follows, and the MonoBehaviour that owns the acquisition. Acquire(MonoBehaviour, string, SaveSchema) makes it; every consumer of the document is handed this one slot.

Remarks

One acquisition, until the owner is destroyed. A second acquisition of the same path is refused, from any owner, the same one included, so every save and load of the file goes through this slot and its schema. Disabling the owner keeps the slot; destroying it ends the slot, cancels its requests that have not run, and lets a new owner acquire the path. A persistent owner, such as one under DontDestroyOnLoad, keeps the slot across scene loads. There is no transfer: hand the slot to the consumers that need it.

Order and snapshots. Requests run in the order they were made, across this slot and LunyScript's requests for the same file. A save copies the document's values when it is accepted. Two consumers that save complete documents replace each other in that order; the slot keeps no record of which values another consumer changed, so consumers that edit different fields keep one shared document, or coordinate before saving.

Every request is entered from the main thread; a development build reports another thread with a LunySaveException.
