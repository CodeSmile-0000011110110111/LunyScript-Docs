The core's one entry point to netcode. Owns the INetworkProvider, refuses the session calls that are a user mistake, and drains the provider's two queues once per tick. AGENTS.md rules 44 to 49.

public sealed class NetworkGateway

Remarks

This is the netcode counterpart of CloudSaveGateway and is deliberately the same shape, because rule 49 poses the same problem rule 52 already solved: the core may not reference the backend, so the core owns an interface and a separate assembly implements it.

This type is one of exactly five places the zero-allocation rule relaxes, named as "the services and network gateway" in AGENTS.md rule 31. What that rule permits is narrow: a request may allocate below a stated ceiling, and a pending request must allocate zero per tick. Tick is on the per-frame path and allocates nothing, which is why both queues are drained with TryDequeue rather than by iterating a returned collection.

No session method throws because the network is unavailable. They throw only for a user mistake, which is starting a session while one is running. Being offline is a state a script reads through Net.IsConnected; rule 45.

Remarks

A provider that answers with less than one object's worth is corrected up to SmallestUsefulTransformStreamBytes, because a budget below that would put the runner in the position of either sending nothing or sending over the budget every tick, and sending over a budget the backend set is the provider's business to report rather than the runner's to hide.

TicksPerSecond

How many times a second the transform stream is sent, whatever the frame rate is. 30 by default, which is the rate the replaced NetworkTransform runs at and the rate docs/netcode-bandwidth.md measured both stacks at.

public double TicksPerSecond { get; set; }

Property Value

double

Remarks

AGENTS.md rule 47 says one stream per authority per tick, and this is what "tick" means: a rate of its own, not the frame rate. A game running at 120 frames a second sends 30 streams a second, and one running at 20 sends 20, because a tick cannot be sent in a frame that does not happen.

Synchronised variables are not on this rate. They publish once per frame, which is what they have done since the milestone that introduced them and what their tests asserts; moving them here is named as its own change in docs/proposals/netcode-transform-stream.md.
