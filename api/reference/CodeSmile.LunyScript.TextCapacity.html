Enum TextCapacity

Namespace
CodeSmile.LunyScript
Assembly
ApiSource.dll

How many bytes a text variable can hold. Declared per variable at build time, because the five capacities are five distinct Unity.Collections.FixedString types and a text variable is stored in exactly one of them.

public enum TextCapacity

Fields

Bytes128 = 128

A FixedString128Bytes slot: 128 bytes of storage, 125 usable.

Bytes32 = 32

A FixedString32Bytes slot: 32 bytes of storage, 29 usable.

Bytes4096 = 4096

A FixedString4096Bytes slot: 4096 bytes of storage, 4093 usable.

Bytes512 = 512

A FixedString512Bytes slot: 512 bytes of storage, 509 usable.

Bytes64 = 64

A FixedString64Bytes slot: 64 bytes of storage, 61 usable.

Examples

var playerName = Var.DefineText("playerName", TextCapacity.Bytes64);

Remarks

AGENTS.md rule 15: Var.DefineText defaults to Bytes64, because 64 bytes is a common cache-line size, and that default is what a caller gets when the content has no known size. Choosing a different capacity deliberately is still the right thing when the content is known to be shorter or longer than the 61 usable bytes of Bytes64; what the enum exists to prevent is one size being imposed on every text variable with no way to change it. Above Bytes4096 there is no fixed string, and that case needs a fallback that is allowed to allocate and allowed to be non-networked. Define.Text(name).Allocating(maxBytes) is that fallback.

The usable payload of each size is three bytes less than the name says: two bytes hold the length and one holds a terminating zero. UsableBytes(TextCapacity) returns the usable figure rather than the name's figure.
