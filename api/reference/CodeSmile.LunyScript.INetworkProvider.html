LunyScript API Reference

Interface INetworkProvider

Namespace
CodeSmile.LunyScript
Assembly
ApiSource.dll

What a netcode backend provides to the NetworkGateway: a session to start and end, the connection facts a script is allowed to read, and two queues the gateway drains once per tick. Script code never sees this type; it sees the Net and Sync surfaces. AGENTS.md rule 49.

public interface INetworkProvider

Examples

runner.NetworkGateway.UseProvider(new FakeNetworkProvider());

Remarks

Two implementations exist, and the tests that matter run against both. FakeNetworkProvider runs two peers in one process with no network and no Editor, which is what makes the message and cadence tests runnable in Edit Mode; it is a second real implementation rather than a mock, in the same way FakeHost is for blocks. NgoNetworkProvider in CodeSmile.LunyScript.Netcode is the Netcode for GameObjects one, and it is the only place in the product that references that package.

Authority, not "server". HasAuthority(int) answers for one object and means owner under distributed authority and server under client-server, which is why a script written against it runs unchanged in either topology. AGENTS.md rule 44.

Nothing here throws because a session is not running. A provider with no session reports Offline, zero peers and no authority. Connection state is a state a script reads, not an exception it handles; AGENTS.md rule 45.

Properties

IsHost

True when this peer is the host. False for a client and for no session at all. Exposed because rule 45 forbids hiding it, and because "works as host, breaks as client" is the defect that hiding it produces.

bool IsHost { get; }

Property Value

bool

MaximumTransformStreamBytes

How many payload bytes of transform stream this backend can carry in one send. The runner splits a tick's stream into as many sends as it needs to stay inside it.

int MaximumTransformStreamBytes { get; }

Property Value

int

Remarks

A transport carries a bounded message. One stream per authority per tick is what AGENTS.md rule 47 requires and it stays true here: the tick still produces one stream, and this is how many bytes of it fit in one message. A hundred objects sending all three channels is about 1800 bytes, which is past what Netcode for GameObjects carries unfragmented, so this is not a limit only an unusual session meets.

Splitting rather than asking the backend to fragment is deliberate. Each piece carries the stream's own 3-byte header and is decoded on its own, so a piece costs about 3 bytes plus whatever the backend's own per-message header is; a fragmented message costs the backend's fragment headers and its reassembly state instead, and leaves the stream depending on a feature that differs between backends.

The buffer the runner encoded the stream into. The provider must copy what it needs before returning, because the runner reuses this buffer next tick.

Remarks

One call per authority per tick, carrying every object that authority has something to send for, rather than one call per object. AGENTS.md rule 47 requires that shape, because one message per object per tick spends about as many bytes on framing as a half-precision position costs.

TryDequeueMessage(out NetworkMessage)

Takes one received message off the queue, if there is one. The gateway drains this until it returns false, once per tick.

bool TryDequeueMessage(out NetworkMessage message)

Parameters

message NetworkMessage

The message, when this returns true.

Returns

bool

False when the queue is empty.

Remarks

A TryDequeue rather than a returned collection, because the gateway drains it every tick and a returned collection would allocate every tick; AGENTS.md rule 29.

TryDequeuePeerJoined(out int)

Takes one "a peer joined" notification off the queue, if there is one. Drained the same way and for the same reason as TryDequeueMessage(out NetworkMessage).

bool TryDequeuePeerJoined(out int peerId)

Parameters

peerId int

The peer that joined, when this returns true.

Returns

bool

False when the queue is empty.

Remarks

This is what makes SyncCadence.Once work for a peer that was not there when the value was first set. Without it, a name chosen by the host before anyone joined would never be sent, because Once sends once and a late joiner missed it. The authority answers a join by marking every synchronised variable unsent, so the next tick sends the current value of all of them.

The resend goes to every peer, not only to the one that joined. This milestone has no per-peer addressing: SendVariable(int, int, in NetworkValue) is a broadcast. The cost is one redundant copy of each synchronised variable per peer per join, which is bounded by the number of joins rather than by the frame rate. Per-peer addressing is part of the transform stream milestone, where rule 47's bandwidth budget makes it load-bearing.

TryDequeueTransformStream(out byte[], out int, out int)

The next transform stream that arrived, as a view into a buffer the provider owns. The view is valid until the next stream arrives.

Remarks

A view rather than an array, because a peer that is not the authority receives a stream on every tick and returning a fresh array would allocate on every one of them. TransformStreamInbox is the implementation both providers use.
