LunyScript API Reference

Namespace CodeSmile.LunySpawn.Unity

Classes

PrefabBinding

One prefab a recipe names by key: the prefab, whether its copies are pooled and how many may exist, the space it needs where it spawns, and a profile text its participants receive, such as a Combat profile. A SpawnBindings asset holds them and the Inspector edits them.

SpawnArea

A bounded area: every candidate is drawn uniformly from its disk, box or ball, in the object's local space, and moved into the world through the object's transform as it is at the attempt. The object's rotation is the rotation every arrival takes.

SpawnBindings

The prefab bindings a SpawnHost resolves a recipe's keys with: one asset per game or per scene, assigned in the host's Inspector, so no recipe names an asset path.

SpawnHost

The scene host of LunySpawn: it owns one SpawnSession, advances it by game time once per frame, resolves a recipe's keys through its SpawnBindings asset and the scene's placements, places, pools and releases the objects, and ends every run with the scene (the captain's Q12 answer: one scene host with separately owned runs).

SpawnPlacement

A scene object a recipe's placement key names: an exact marker (SpawnPoint) or a bounded area (SpawnArea). Its pose is read on every attempt, so a moving portal moves the arrivals that follow (the captain's Q43 answer); the session records each candidate with its decision.

SpawnPoint

An exact marker: every candidate is this object's position and rotation at the attempt.

SpawnedObject

The marker a SpawnHost adds to every object it spawns: it names the object's current use, and it reports the use as Removed when something other than the host destroys or deactivates the object, which clears the member (the captain's Q29 answer: absence is completion).

Structs

RunStart

What StartRun(SpawnRecipe, Object, int) did: the started run, or every problem that refused it: a prefab key with no binding, a pooled prefab with an uncovered component, a placement key with no marker or area in the host's scene, or a degenerate area. Content is admitted before anything runs.

SpawnUseContext

What a participant learns about the use it begins.

Interfaces

ISpawnParticipant

A component on a spawned object that takes part in each of its uses: it begins a use after the object was placed and activated, and may refuse it, and it ends the use before the object is returned to its pool or destroyed. A component that implements it resets its own state in BeginUse(in SpawnUseContext), which also covers it for pooling (the captain's Q23 answer: every component of a pooled prefab has an admitted reset or retain policy).

ISpawnRetainsState

Marks a component whose state deliberately carries from one use of a pooled object to the next, such as a cached reference or a mesh it built once. It covers the component for pooling without a reset.
