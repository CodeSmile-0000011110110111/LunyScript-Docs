Gate 4. Runs inside a standalone player built without DEBUG and asserts what only that build can show: that operator true and operator false on a condition block still throw, that the [Conditional] contract guards are gone, and that the two guards written out unconditionally are not.

Remarks

AGENTS.md rule 38 says the two operators throw in release builds as well as debug, and that wrapping them in #if DEBUG is not allowed. Every run the Test Runner can produce defines DEBUG: the Editor does, and Player mode builds a development player. So the rule cannot be checked by a test alone, and this entry point exists instead.

The gate is compiled in only when LUNY_RELEASE_GATE is defined, which PlayerBackendSettings.SetReleaseGate does and nothing else does. It quits the player with exit status 0 when every check passed and 1 when any failed, and writes one line per check so the log says which.

Its first check is its own premise: it fails when DEBUG turns out to be defined, because a pass under DEBUG would prove nothing about a release build.

Two of its checks are a matched pair and neither means much without the other. CodeSmile.LunyScript.ReleaseGate.ContractGuardsAreCompiledOut() passes when a [Conditional] guard does not throw in a build without DEBUG; CodeSmile.LunyScript.ReleaseGate.UnconditionalGuardsStillThrow() passes when the two guards that are deliberately unconditional do throw in that same build. Together they are what makes AGENTS.md rule 71's "a guard may be conditional only where the failure its removal gives up is loud" a measured rule rather than a stated one.

Remarks

Tools/run-tests.sh greps the player log for this exact phrase, so it is composed from the one logging surface rather than written out again here; AGENTS.md rule 60. Changing either half changes what gate 4 reports.

Methods

Run()

Runs the checks and returns how many failed. Callable from a test as well, which is what makes the same assertions visible in the Editor and in the development players; only the first check can differ between them, and it is the one the release build exists for.

public static int Run()

Returns

int

RunOperatorChecks()

Runs only the two operator checks, without the check that DEBUG is absent. A test calls this, because the Editor and every development player define DEBUG and would fail the premise check while the operators themselves behave correctly.
