One step of behaviour in a script. A block object is created once, when its script type is built, and is then shared by every object running that script; the per-object state it reads and writes lives in slots on the ScriptInstance passed to Execute(ScriptInstance).

Remarks

Every field of every block is readonly, and a structural test enforces it, because one tree serves every object running the script and a mutable field would be shared state across all of them. AGENTS.md rule 22. A block holds slot handles, literals and child block arrays, and nothing else: no List, no Dictionary, no cached host and no cached component.

Location

Where in the user's script this block was authored, captured when it was built.

public SourceLocation Location { get; }

Property Value

SourceLocation

Examples

var where = block.Location.Describe();   // "Assets/Scripts/CountdownScript.cs:12"

Remarks

This is the only place a block's own source line can come from. A block is composed inside Build() and executed much later by ScriptRunner, so at the moment it logs or throws the user's line is not on the call stack at all; the factory method that built it captured the line with [CallerFilePath] and [CallerLineNumber] and handed it here. SourceLocation states what that costs, which is one reference and one int per block and no allocation.

A block built by a C# operator, such as the NumberArithmeticBlock behind health + 1.0, carries Unknown: an operator cannot declare the optional parameters the caller attributes need. The block that consumes such an expression carries the location instead.

Remarks

A result and a failure are different things and this is where they separate: an action reports Failed through its own specified domain-failure behaviour, while an exception thrown out of it is attributed here and propagated to the runner's boundary, which stops the instance. docs/execution-model.md, "Contained action failures".
