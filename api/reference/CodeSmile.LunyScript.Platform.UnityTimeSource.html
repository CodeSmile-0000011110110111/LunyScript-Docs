The time source a running game uses: Unity's own frame clock, read once per call from UnityEngine.Time, with Unity's Time.timeScale as the game's time scale.

Remarks

This is the default a ScriptRunner constructs for itself, so nothing has to be wired up for a rate-capped SyncCadence to advance in a real game. A test installs TestKit.ManualTimeSource instead, which is what makes a cadence test deterministic rather than dependent on how long a frame happened to take.

Every value is read on every call rather than cached, because Unity updates them per frame and a cached value would be one frame stale for every caller after the first. Reading them allocates nothing.

The scale is Unity's own, and this class stores exactly one thing: what Resume() should come back to. Keeping a second copy of the scale here would let it disagree with Time.timeScale the moment any other code wrote that, and other code does: Unity's own pause menu samples, a timeline, an editor tool. So Scale always reports what the engine is actually running at, and the one thing this clock remembers is the last positive scale it was asked for.

Methods

Pause()

Stops game time by setting the scale to zero. The scale to come back to is remembered. Pausing an already paused clock changes nothing.

public void Pause()

Resume()

Restarts game time at the last positive scale this clock was set to, which is one when none was. Resuming a clock that is not paused changes nothing.
