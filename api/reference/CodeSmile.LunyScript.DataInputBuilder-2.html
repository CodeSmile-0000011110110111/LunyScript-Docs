What Bind.Data(schema) returns: an Inspector data input, or with a From... call a JSON file of that schema.

public readonly struct DataInputBuilder<TValue, THandle> where TValue : struct where THandle : struct, ILunyScriptDataVariables

Type Parameters

TValue

The schema struct.

THandle

Its generated Variables.

Expand Details ...

Examples

Balance = Bind.Data(WeaponStats.Schema);
StatsFile = Bind.Data(WeaponStats.Schema).FromStreamingAssets("weapon.json");
LootTuning = Bind.Data(LootStats.Schema).Shared();

Remarks

Assigned as it is, it declares an Inspector input. The object's LunyScript Behaviour shows a field that accepts a data asset, and when the object spawns, before On.Ready, the one LunyScriptDataFieldAttribute field of that schema on the asset is copied into this object's variables. The asset keeps its values. An object that assigns nothing refuses to spawn, because rules data has no placeholder.

FromStreamingAssets, FromUserData and FromTemp name a JSON file instead, which Asset.Load(file).Into(data) reads into a Define.Data of the same schema.

Shared() makes it one copy every script reads: the first object that spawns with an asset assigned fills it, and an object may leave its field empty.

Examples

On.Ready(Gold.Set(LootTuning.GoldWeight));

Remarks

The first object that spawns with an asset assigned fills the copy, before its On.Ready, and the asset's values are the copy's defaults, which Shared.Clear() restores, for as long as the runner runs. An object may leave its field empty and reads the copy; until an object with an asset spawned, the fields hold zero, false, empty text and the zero vector. An object whose asset holds other values is refused, with an error naming the field and both values; an object with the same asset, or one with equal values, writes nothing. The schema's fields are numbers, bool, string and Vector3, the kinds a shared store holds.
