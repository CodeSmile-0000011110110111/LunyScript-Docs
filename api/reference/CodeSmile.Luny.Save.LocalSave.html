Class LocalSave

Namespace
CodeSmile.Luny.Save

Saves and loads typed documents on this device, for plain C#. Acquire(MonoBehaviour, string, SaveSchema) binds a path in the player's writable data folder, a SaveSchema and the MonoBehaviour that owns them into a SaveSlot, which saves, loads, tests and deletes that one document; AcquireGroup(MonoBehaviour, string, SaveGroupSchema) does the same for a SaveGroupSlot, several documents saved as one archive. LoadStreamingAsset(MonoBehaviour, string, SaveSchema) reads a document the build ships, List(SaveCollection) lists the saves of a folder, and Journal keeps the last requests for a support report.

Remarks

Two folders, both chosen by the platform. The writable folder is Application.persistentDataPath, the one place Unity guarantees a player may write on every platform, and the read-only folder is Application.streamingAssetsPath, which holds the build's copy of Assets/StreamingAssets. Acquire(this, "savegames/001.sav", Progress) names <persistentDataPath>/savegames/001.sav. There is no call that writes to StreamingAssets, takes an absolute path, or reads a file's bytes, and a path that leads through a linked folder below the platform's folder is refused when a request runs.

One owner per path. A path is acquired once, by one living owner, until that owner is destroyed; a second acquisition throws a LunySaveException. Requests for one path run in the order they were made, across slots and LunyScript's script documents. LunySave is entered from the main thread; a development build reports another thread. One application process: another process writing the same files is outside what LunySave orders.

What a save guarantees. A save writes the whole document to a copy beside the file, flushes it, and replaces the file in one rename, so a failure leaves the previous copy as it was. A load reads the file, runs the schema's migration steps on a copy of an older version, and checks every declared field before it hands back a document; it never writes the file and never reads another copy in its place. The files are plain JSON the user can read and change; LunySave promises no secrecy and no protection against edited values, which a game checks when it applies them.

Exceptions

LunySaveException

The owner is null or destroyed, the path is refused, the schema is null or its steps leave a gap, the path is acquired already, or the call is from another thread in a development build.
