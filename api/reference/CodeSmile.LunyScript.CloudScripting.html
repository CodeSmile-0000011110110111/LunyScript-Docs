LunyScript API Reference

Class CloudScripting

Namespace
CodeSmile.LunyScript
Assembly
ApiSource.dll

The Cloud verbs a script writes inside Build(): save, load and delete a declared document, a key of the player's data, a game data item or a player file, each bound to an operation handle with .As(handle), and Cloud.CommitIs, the commit status of a write. Outcomes arrive through When.Cloud(handle) and When.Operation(handle). AGENTS.md rule 50.

Remarks

LunyCloud adds these to the core's CloudFactory surface as extension methods in namespace CodeSmile.LunyScript, so a script writes Cloud.Save(Career).As(Uploading) as before, with no using line (docs/proposals/lunycloud.md L01). A request for one key runs after the requests before it for that key, in the order their blocks ran; the backend owns the timing and LunyScript adds no deadline. docs/proposals/cloud-documents.md is the contract for documents, docs/proposals/lunycloud.md for the rest.

CommitIs(CloudFactory, Operation, CloudCommit, string, int)

True when the last cloud write bound to handle ended with the commit status commit (C09 A): Confirmed after success; NotSubmitted when the write never reached the service or the service did not take it; Unknown when it was sent and failed in a way that may have written, or was cancelled after it was sent. None before the write ended. A failure keeps its classification; this says whether the service may hold the write, and nothing is resent because of it.

Starts uploading the document: every field's value when the block runs, stored as one value that replaces the cloud copy under the document's name, or under the key .To(key) names. Once the cloud confirms an upload to the document's own name, Unsynced is false unless a field was edited since the block ran.
