LunyScript API Reference

Namespace CodeSmile.LunySpawn

Classes

GroupSpec

One group of a phase as C# writes it: what it spawns (a prefab binding key), where (a placement binding key), how many for one to four participants, and its timing. From(RecipeSpec) validates it with the rest of the recipe.

LunySpawnException

A mistake in a call to LunySpawn: a missing argument, a handle of another session, or content the caller was told to admit first. A refused spawn, a blocked placement or a failed run is never an exception; it is a result with its reason.

PhaseRule

Creates the terms of a phase's success condition.

PhaseSpec

One phase of a recipe as C# writes it: its groups, which run together, the condition that ends it with success, the signals that fail the run while it is current, and what happens to its live objects when it ends.

PhaseTerm

One term of a phase's success condition: named groups clear, game time elapsed in the phase, or a declared signal latched. PhaseRule creates them.

RecipeAdmission

What admitting a recipe produced: the validated, immutable Recipe, or every problem that refused it. Admission never throws for content, so a tool lists every problem at once; Require() throws when the content is expected to be valid.

RecipeSpec

A spawn recipe as C# writes it: its ordered phases, the signals it declares, the signals that fail it in any phase, and the retry policy its groups default to. From(RecipeSpec) validates it into an immutable SpawnRecipe; an encounter file in Luny/Encounter/ is read into the same spec.

SpawnGroup

One admitted group of a SpawnRecipe: what it spawns, where, how many for each participant count, its timing, how it stops, and its retry policy with the values that actually apply.

SpawnJournal

The session's bounded ring of records. A reader keeps a SpawnCursor and reads at its own pace; the ring keeps the newest Capacity records.

SpawnPhase

One admitted phase of a SpawnRecipe: its groups, its success condition, the signals that fail the run while it is current, and its survivor policy.

SpawnProblem

One problem a recipe admission found: where it is, as a path such as phases[1].groups[0].counts, the encounter file and line when the recipe came from one, and what is wrong.

SpawnRecipe

An admitted, immutable spawn recipe: ordered phases of concurrent groups (the captain's Q16 answer), the signals a run accepts, and the content revision it came from. A run keeps the recipe it started with for its whole life, so an edited file takes effect in the next run (Q22).

SpawnSession

The plain C# spawn director of one scene: it runs any number of recipes, each a separately owned run with its own seed, phases, groups and objects (the captain's Q12 answer), shares one live population limit and one attempt budget between them, and asks its ISpawnWorld to place and release objects. A Unity SpawnHost owns one per scene and advances it by game time; a test advances it by hand.

Structs

AttemptResult

The outcome of one admission attempt, with the candidate pose the world observed, which the session records.

GroupRead

A snapshot of one group of a run: its status, counts, what its pending members wait for and its last refusal.

RecordPage

One read of the journal: how many records were copied and how many the reader missed because the journal dropped them before it read.

RunRead

A snapshot of one run: its state and result, recipe, revision, seed, phase, counts and the pressure its future cohorts use. Reading allocates nothing.

SpawnAttempt

One member a session asks its world to admit.

SpawnCursor

A reader's position in a SpawnJournal; each reader keeps its own.

SpawnRandom

One group's deterministic random stream: xorshift64* seeded with SplitMix64 from the run's seed and the group's id (the captain's Q34 answer: an explicit seed per run with independent streams per stable group). The same seed, recipe and recorded observations give the same candidate choices; editing one group leaves every other group's sequence unchanged.

SpawnRecord

One structured record of what a session did, in the order it did it: the inputs it observed and the decisions it made, so a run can be explained and reproduced (the captain's Q32 and Q34 answers). Keys are indices into the run's recipe, so writing a record allocates nothing.

SpawnRefusal

Why one attempt to admit a member was refused: the code a caller branches on and a sentence for a log line. An admitted member's result carries the code None and an empty message. Reading it allocates nothing.

SpawnRun

The handle of one run of a recipe in a SpawnSession. It carries the run's generation, so a handle kept after the run was released reads IsValid false and its commands are refused; it never reaches a later run in the same slot (the captain's Q41 answer: stale handles are refused).

SpawnSessionOptions

The limits of a SpawnSession: its live population, its attempt budget per boundary and how many records it keeps.

SpawnUse

The identity of one admitted use of an object: fresh for every use, also when a pooled object is used again, so a callback that holds an earlier use's handle cannot change the next one.

Interfaces

ISpawnWorld

What a SpawnSession asks of the world it spawns into: try one admission, and release an object whose use ended. The Unity layer's SpawnHost implements it over prefabs, scene markers and physics; a test implements it with plain objects.

Enums

CohortSample

Whether a completed cohort is a clear-speed sample, and if not, why (the captain's Q46 answer).

ConditionMode

How a phase's success terms combine.

GroupKind

How a group emits: one finite cohort, or one finite batch per interval until it is stopped.

GroupStatus

Where a group is in its run.

RecordKind

What a SpawnRecord reports. Its fields say which of the record's fields each kind fills.

RunEnd

Why a run reached its terminal state; EndDetail names the signal or group.

RunState

Where a run is in its life. A run admits objects only while Running; the three terminal states keep their result until the run is released.

SignalResult

What a raised signal did.

SpawnRefusalCode

Why one attempt to admit a member was refused, the Code of Refusal and LastRefusal. Each refusal waits the group's retry interval and counts against the member's deadline.

SpawnTier

The strength tier a cohort's prefab binding is chosen from (the captain's Q47 answer: three declared tiers per enemy role; the role and its quota stay the same).

Survivors

What happens to a phase's live objects when the phase ends (the captain's Q28 answer).

TermKind

The three kinds of term a phase's success condition may hold (the captain's Q27 answer: a small closed set, no executable expressions).

UseEnd

Why a use ended. Any end clears the member (the captain's Q29 answer: absence is completion); only Defeated is evidence for the clear-speed controller.

WaitReason

Why a due member has not been admitted yet, for inspection.
