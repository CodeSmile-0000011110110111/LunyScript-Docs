A handle to one variable of a script. Returned by Var.Define at build time; the operators and methods on it build blocks.

public readonly struct Var<T> where T : struct

Type Parameters

T

What the variable holds: Number, Flag, Text, Vec3, Rotation, Vec2 or a declared C# enum. AGENTS.md rule 12 makes Number the number type, so there is no Var<Int32> and no Var<Single>.

Expand Details ...

Examples

var health = Var.Define<Number>("health", 100.0);
On.FrameUpdate(If(health > 10).Then(health.Add(-1)).Else(health.Set(0)));

Remarks

The handle is an index, not a value: it says where the variable lives on every instance of the program, and the same handle reads a different number on every object running the script.

A handle is valid only inside the Build that declared it. It carries a slot index and a kind and nothing that identifies its program, so a handle from one script used in another script's Build addresses that other script's slot of the same index. Take a ScoreScript holding static Var<Number> Score at index 0, and a PickupScript whose own first variable is cooldown: writing On.Ready(ScoreScript.Score.Add(10.0)) inside PickupScript.Build adds 10 to every pickup's cooldown and never moves the score. Where the borrowed index is past the end of the borrowing program's array, ScriptInstance throws LunyScriptUsageException naming this cause; where it is within range, as here, nothing detects it. Declare each script's variables in its own Build.

An operation the variable's kind does not support throws at build time, not at compile time. health.Add("text") is a compile error, because Add takes T. But playerName + 1 compiles and then throws LunyScriptUsageException while the script type is built, because C# 9 has no static abstract interface members and an operator declared on a generic type therefore cannot be restricted to one instantiation of it. Build runs once per script type at launch, so a script that can throw one of these throws it on the first run. docs/slice-decisions.md records the alternative that was rejected.

operator == on a handle builds a condition block; it does not compare handles. Use Equals(object) to compare two handles.

Remarks

This and the members below it are one-line pass-throughs to the same members on Vec3ValueBlock and RotationValueBlock, and they exist because C# applies no user-defined conversion before a member access: without them, Spawn.Length would not compile even though Spawn converts to a spatial expression wherever one is expected.

The C# operators are the one part this cannot cover. Spawn * 2.0 does not compile, because operator lookup also runs on the operands' own types and neither is a spatial expression. Put the variable in a local of the expression type first - Vec3ValueBlock spawn = Spawn; - and the operators are available on it.

Negate(string, int)

Builds a block that writes this variable's own value back with the opposite sign, so a direction reverses without its magnitude being named.

public Block Negate(string callerFilePath = null, int callerLineNumber = 0)

Parameters

Type Name Description
string
callerFilePath

Supplied by the compiler. It records the line this block was written on, so a later failure names that line rather than LunyScript's own source.
int
callerLineNumber

Supplied by the compiler.

Returns

Block

A block to place in an event list.

Examples

On.FrameUpdate(If((travelledX > 3.0) & (step > 0.0)).Then(step.Negate()));

Remarks

Which shape is right for a ping-pong, stated because the obvious one is wrong. Negate is not idempotent: Set(-0.02) run twice leaves the same value, Negate run twice leaves the original value. So a single condition on position alone,

If(travelledX > 3.0).Then(step.Negate())      // wrong

flips the sign on every frame that condition holds. An object that leaves the bound within one frame turns around once and nothing looks wrong; an object that lingers past the bound for n frames flips n times and vibrates in place. Guard on the direction of travel as well as the position, and give each bound its own condition:

If((travelledX > 3.0) & (step > 0.0)).Then(step.Negate()),
If((travelledX < -3.0) & (step < 0.0)).Then(step.Negate())

After the first flip step > 0.0 is false, so further frames spent past the bound change nothing, and the magnitude the flip preserves is whatever the variable held. docs/proposals/var-negate.md states the reasoning and SliceScript is written in this shape.

Negating 0 produces negative zero, which compares equal to 0 in every comparison this API builds, so a step == 0.0 test answers the same before and after.

Exceptions

LunyScriptUsageException

This is not a Number variable.
