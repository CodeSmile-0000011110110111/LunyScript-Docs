Struct TransformTargetFactory

Namespace
CodeSmile.LunyScript

One step of the hierarchy around the object a script runs on: what Transform.Parent, Transform.Child(n) and Transform.Root return.

public readonly struct TransformTargetFactory
Expand Details ...

Examples

On.FrameUpdate(Transform.Child(0).RotateBy(0.0, 1.0, 0.0));

Remarks

It offers no Parent, Child or Root of its own, so Transform.Parent.Parent does not compile and a chain cannot walk an arbitrary path. That bound is the point rather than an omission: a deeper path is a different object on every frame as soon as anything reparents, and docs/positioning.md item C14 is where naming an object properly arrives. TransformRelation states the same thing.

What it does offer is every verb the object's own surface offers, aimed at the object the relation names. Each verb is written and documented once, here: TransformFactory forwards its verbs to an instance of this type aimed at the object the script runs on.

WorldRotationX

Property Value

NumberValueBlock

Examples

On.FrameUpdate(Pitch.Set(Transform.Child(0).WorldRotationX));

Remarks

Euler degrees rather than a quaternion, because that is what a script author writes. Unity derives the three angles from the rotation it holds, and more than one set of angles names the same rotation, so reading these back after writing them can give a different set that turns the object the same way.

Parameters

int

A block to place in an event list.

Examples

On.Ready(Transform.ScaleBy(2.0, 1.0, 2.0));
On.Ready(Transform.Child(0).ScaleBy(2.0, 1.0, 2.0));

Remarks

A factor, not an amount: one leaves the axis unchanged, zero collapses it and a negative factor mirrors it. Repeated every frame it compounds, which is what makes it a growth rather than a step. There is no world modifier and no AddScale verb; that is the captain's answer to API-semantics row T03 on 2026-09-13.
