Remarks

This is a second real implementation rather than a test mock, in the same way FakeNetworkProvider is: it answers every member of IInputProvider with the same rules the Input System adapter answers them with, occurrences aside, which is what makes the input tests runnable in Edit Mode and what lets a project without the package still run a script that reads input.

A test configures it the way an action asset is configured - name the actions and their kinds - and then drives them: SetNumber(int, string, double), SetVector(int, string, double, double, double) and SetPressed(int, string, bool) write the last value an action received, which every read returns in every event until the test writes another, and Raise(int, string, InputPhase) marks an occurrence as having happened in the frame that is running. EndFrame() clears the occurrences, which is what a real backend's next frame does. The adapter records an occurrence as it arrives and hands it to the next frame update in BeginFrame(); here a test places it in a frame directly, so BeginFrame() changes nothing.

Bindings are one path per action and one per part. AddAction(int, string, InputValueKind, bool, string) takes the path the action asset would give the action, and AddPart(int, string, string, string) adds a composite part with its own path. A rebind, a reset and a load change the override that sits on top of each, which is what BoundControl reads and a Settings document saves; the key of an override is the action's name, or action/part for a part.

Players are fixed until UseLocalPlayers(int) is called. By default the first SetLocalPlayerCount(int) numbers are present from the start and pairing is refused, which is what the Input System adapter's one-player setup does. After UseLocalPlayers(int) nobody is present, and a test pairs players with the same rules the adapter applies: PressDevice(string) is a button press on a named device, DisconnectDevice(string) and ReconnectDevice(string) unplug and replug it, and every change is applied by UpdatePairing(), which the gateway calls once per frame.

After UseLocalPlayers(int), numbers 0 and 1 both name the host. The first device paired is the host's, and later devices pair guests 2, 3 and so on. An action added for number 0 or 1 is the host's one action, so a test adds it once, under either number, and every member that takes a local player number reads and writes it through both.

Parameters

The identity, 0 for nobody and for a number the backend cannot hold.

Remarks

The identity changes when a different person takes the number, and stays the same when the same person's device is lost and regained or re-paired, which is what the settled contract-player-identity answer asks of a participant. A backend must not hand out the same identity to two people during its lifetime; the gateway maps it to a counter of its own, so two backends may use the same numbers.

Two numbers that answer the same identity name one person. A backend that pairs its own players answers its host's identity on numbers 0 and 1, and the gateway then gives both numbers one participant and counts that person once.

UpdatePairing()

Applies every pairing change requested or detected since the last call. Called once per frame by the gateway before any script instance runs, so every script sees the same players during one frame. Must allocate nothing when nothing changed.

public void UpdatePairing()

Remarks

Leaves are applied first and then presses, in the order the test made them. A press on a device a player holds does nothing. Otherwise the device goes to the lowest-numbered player whose device is lost, who keeps their participant, and only then, while pairing is open, to the host when nobody holds the host yet, and to the lowest free guest number after that, as a new participant.

UseLocalPlayers(int)

Switches to paired players: nobody is present, and up to capacity players pair through PressDevice(string) while pairing is open. The first is the host, whom numbers 0 and 1 both name, and the others are guests 2 up to capacity. This is what new InputSystemProvider(actions, capacity) does.

public void UseLocalPlayers(int capacity)
