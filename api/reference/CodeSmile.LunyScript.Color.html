Remarks

The name is Unity's, and the namespace is LunyScript's. This type is CodeSmile.LunyScript.Color, kept apart from UnityEngine.Color by its namespace, for the reason Vector3 gives: a script imports no engine namespace, so Color in a script names this type. A file that imports both CodeSmile.LunyScript and UnityEngine writes UnityEngine.Color for Unity's type.

The channels are public fields that Unity saves. The type carries [Serializable], so a Color field of a ScriptableObject, a MonoBehaviour or a [Serializable] struct is saved with the asset or scene and shown in the Inspector as four numbers. The captain selected public writable fields for engine-free value types on 2026-09-28.

The channels are Double. A script writes colour.R = 0.5 and new Color(1, 0.5, 0) with no f suffix and no narrowing conversion error, which is what AGENTS.md rule 12 promises for every number a script writes. Each channel is narrowed to Unity's Single once, where the colour is written into Unity, which is rule 13's seam.

A channel is not clamped. A value above 1 is kept, because an HDR colour property uses it as intensity. A write that reaches Unity refuses a channel that is negative, not a number, or beyond the largest Single, and says so once; the colour itself stores what it was given.
