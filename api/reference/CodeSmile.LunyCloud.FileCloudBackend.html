The file backend: accounts, player data, game data, player files and leaderboards kept in five kinds of JSON file under one directory. A first-class part of the product, not a test fixture (AGENTS.md rule 52): it is how every branch is reached without a network, and what makes the automated suite run with no credentials.

Remarks

Every call does its work inside the call; the client observes the outcome at its next poll, so a caller sees the order of events it sees against a service, one frame later instead of many. DelayCompletion(int) holds each outcome back for a number of polls, and FailNext(CloudFailure) fails the next call with a chosen reason.

The files (docs/proposals/lunycloud.md L04): account.json (the cached session, the next id, public names and deleted accounts), players/<id>/data.json (one JSON value per key), players/<id>/files.json (each file's bytes in base64), game-data.json (collections of items, written with PutGameData(string, string, string)) and leaderboards.json (each board's entries and past seasons). Keys are JSON member names, so they stay case sensitive on every file system. An agent reads the whole state of a test in these files.

It behaves as Unity's services are documented to: a sign-out keeps the cached session, a deleted account's data stays unreachable, a delete of an absent key succeeds, and a leaderboard keeps the best, latest or summed score by the declared rule, ranks by the declared order, and clears its entries when a season ends (EndSeason(string)).

DelayCompletion(int)

Makes every later call report that it is complete only after the client polled it polls times, once per frame. The work still happens inside the call, as a service can store a value before its answer arrives. 0, the default, reports each outcome at the first poll.
