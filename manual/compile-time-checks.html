Compile-time checks

LunyScript checks your scripts while Unity compiles them. A mistake that would otherwise fail when the script type is built, or would silently do nothing, is reported on its own line in the Console and in your IDE, with an ID you can look up here:

public sealed partial class Guard : Script
{
    protected override void Build()
    {
        Health = Number.Define(nameof(Health), 100);

        if (Health > 10)                       // LUNY002: an error
            On.FrameUpdate(Health.Subtract(1));

        Transform.MoveBy(1, 0, 0);             // LUNY005: a warning

        On.FrameUpdate(If(Health > 10).Then(Health.Subtract(1)));
        On.Ready(Transform.MoveBy(1, 0, 0));
    }
}

The last two lines are the forms the first two meant. The checks ship in the same DLL as the generator that writes your variable properties, so there is nothing to install or enable.

ID Severity What it reports
LUNY001 Error A variable or asset declaration the generator cannot complete.
LUNY002 Error A condition used as a C# bool.
LUNY003 Warning A variable whose name hides one of the script’s own surfaces.
LUNY004 Error A builder written as a statement before it is finished.
LUNY005 Warning A block written as a statement, where nothing runs it.
LUNY006 Warning Unity engine API called from inside a script.

LUNY001: a declaration the generator cannot complete

The generator writes a property for each Define line and each [Variable] or [Asset] property. When it cannot, it says why and what to write instead: the class is not partial, the nameof names a different property, the variable is used above the line that declares it, or a second line declares the same name.

public sealed class Guard : Script  // LUNY001: Add partial to class Guard

Where your IDE offers code fixes from the project’s analyzers, it offers Add partial on this error. The fix adds partial to the class, and to every class it is nested in that needs it. The compiler reports the error and applies no fix, so in Unity alone you add partial yourself.

LUNY002: a condition used as a C# bool

Build() composes blocks once, and the blocks run later, on every object that runs the script. A C# if, while, for, do, ?:, a bool variable or a (bool) cast would have to decide a condition while Build() runs, when there is no object to ask. The message names the values the condition reads:

if (Health > 10) { }        // Blocks (here: Health) cannot be compared
                            // outside block sequences
bool alive = Alive.IsTrue();  // the same error, here: Alive

Pass the condition to If(...) instead. &&, ||, &, | and ! between conditions build one combined condition, so they are not reported:

On.FrameUpdate(If(Health > 10 && Alive).Then(Health.Subtract(1)));

The same line also throws when the script type is built, in every build configuration.

LUNY003: a name that hides a script surface

Time, Object, Input, Run, Seconds, Progress and every other surface you call inside Build() are members of the script. A property or field with the same name hides that member inside the script, so Time.Delta stops compiling there:

[Variable] public Number Time { get; private set; }   // LUNY003

A Define line that uses a surface’s name cannot declare a variable at all, because the name already means the surface. The compiler reports that the member is read-only or a method, and LUNY003 on the same line says why:

Progress = Number.Define(nameof(Progress), 0);  // LUNY003

Name the variable after what it holds, such as RoundTime or LevelProgress. A declaration written with new hides the surface on purpose and is not reported.

LUNY004: a builder that is not finished

A call such as When.Operation(Load) or If(Alive) starts a builder, and the builder does nothing until its chain is finished. Written as a statement on its own, it is reported with the call that started it and what is still missing:

When.Operation(Load);  // Builder (here: When.Operation(..)) is
                       // incomplete: it does not have blocks to run
Scene.Load(Arena);     // Builder (here: Scene.Load(..)) is
                       // incomplete: finish it with .Additive() or .As(..)

Finish the chain, and pass it to an event where it is a block:

When.Operation(Load).Failed(Health.Set(0));
On.Ready(Scene.Load(Arena).As(Load));

The script type is also refused when it is built, naming the builder and the line. That refusal still covers a builder that is stored in a variable or returned from a method and never finished, which the compile-time check does not follow.

LUNY005: a block that nothing runs

A block runs only when it is registered against an event or placed in a sequence. Written as a statement, it is composed and then dropped:

Transform.MoveBy(1, 0, 0);  // Builder (here: Transform.MoveBy(..))
                            // block is unused, it will not run
Health.Set(0);              // Block (here: Health.Set(..)) is unused,
                            // it will not run

Pass it to an event, or keep it in a variable and pass that:

var step = Transform.MoveBy(1, 0, 0);
On.FrameUpdate(step);

A builder written this way, such as Transform.MoveBy(..), is also refused when the script type is built. A finished block such as Health.Set(0) is not, so this warning is the only report of it.

LUNY006: Unity engine API inside a script

A script’s own code runs once, when the script type is built, and reaches game objects only through LunyScript blocks. An engine call there acts on the whole game at that moment: it can change the time scale, load a scene, or destroy an object LunyScript manages. The warning names the member with its namespace, so a script surface and an engine class with the same name are told apart:

UnityEngine.Time.timeScale = 0f;  // LUNY006
On.Ready(Time.SetScale(0));       // the LunyScript surface

Every member of the UnityEngine, UnityEditor and Unity namespaces is reported inside a class derived from Script, EditorScript or ScriptBase, including its helper methods and property getters. Engine types in declarations, such as [Asset] public Asset<Texture2D> Poster, and attributes are not calls and are not reported. Code in other classes is not checked, so the warning is a hint for the common case.

Turning a check off for a few lines

LUNY002 to LUNY006 are ordinary compiler diagnostics, so #pragma warning turns one off around the lines that need it and on again after them:

#pragma warning disable LUNY005
Transform.MoveBy(1, 0, 0);
#pragma warning restore LUNY005
