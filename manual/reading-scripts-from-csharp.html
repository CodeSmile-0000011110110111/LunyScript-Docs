Reading scripts from C#

Show a script’s variable in an ordinary MonoBehaviour:

using CodeSmile.LunyScript;
using UnityEngine;

public sealed class HealthBar : MonoBehaviour
{
    [SerializeField] private LunyScriptBehaviour m_Player;
    [SerializeField] private Transform m_Bar;
    private ScriptView<PlayerScript> m_View;
    private ScriptObservation m_Watch;

    private void Start()
    {
        m_View = Scripts.Find<PlayerScript>(m_Player);
        if (m_View.Exists == false)
            return;

        var player = m_View.Definition;
        ShowHealth(m_View.Read(player.Health));
        m_Watch = m_View.Observe(player.Health, ShowHealth);
    }

    private void ShowHealth(double health) =>
        m_Bar.localScale = new Vector3((float)(health / 100), 1f, 1f);

    private void OnDestroy() => m_Watch?.Dispose();
}

Scripts.Find looks up the script the player object runs and returns a view of it. Read returns the value Health holds now, and Observe calls ShowHealth again whenever that value changes. The C# code reads; it never writes the script’s variables. In the Inspector, drag the player object onto m_Player, which assigns its LunyScriptBehaviour, and the bar object onto m_Bar, whose width then follows Health.

Finding a script

Scripts.Find<PlayerScript>(behaviour) returns a ScriptView<PlayerScript>. Check Exists before you use it:

var enemy = Scripts.Find<EnemyScript>(behaviour);
if (enemy.Exists)
    damage = enemy.Read(enemy.Definition.Damage);

Exists is false when the object’s script is of another type, when behaviour is null or its object was destroyed, before the object’s Awake, and after the script despawned. A script type derived from the one you ask for is found too.

From a GameObject or a Collider, reach the behaviour first:

private void OnTriggerEnter(Collider other)
{
    if (other.TryGetComponent(out LunyScriptBehaviour behaviour))
    {
        var enemy = Scripts.Find<EnemyScript>(behaviour);
        if (enemy.Exists)
            TakeDamage(enemy.Read(enemy.Definition.Damage));
    }
}

TryGetComponent finds the behaviour on the collider’s own object. A collider on a child object finds the child’s behaviour, not one on its parent.

The definition and its handles

Definition is the script object whose Build() ran. Its properties hold the variable handles: player.Health is the Number that Build() declared. Take the handles from the view you read through. A handle from another script type is refused with a LunyScriptUsageException that names both types, even when both scripts declare a variable of the same name:

view.Read(crate.Definition.Health);   // throws: CrateScript declared Health

A script object you create with new PlayerScript() is not a definition. Its properties are unassigned, because Build() runs once per script type, on the first object of that type.

Reading a value

Read has one form per kind of variable, and each returns that kind:

Variable Read returns After the script ended
Number double 0
Flag bool false
Var<Vec3> Vec3 (0, 0, 0)
Var<Rotation> Rotation Rotation.Identity
Var<Vec2> Vec2 (0, 0)
Var<YourEnum> YourEnum the value whose code is 0
Text a copy into your fixed string an empty string

A text variable is copied into a fixed string you provide, so the read allocates nothing:

var name = new FixedString64Bytes();
view.Read(view.Definition.PlayerName, ref name);

That read returns CopyError.Truncation, and leaves the fixed string unchanged, when the text does not fit. FixedString64Bytes is in Unity.Collections. No read allocates, so a HUD can read every frame.

When the script ends

A view belongs to one run of the script on one object. When that script despawns, or its object is destroyed, Exists becomes false and stays false. A read after that returns the value in the last column of the table above, and the first such read writes one warning to the Console naming the script and the variable. Later reads through the same view write nothing, so a view read every frame writes one line.

LunyScript reuses a despawned script’s storage for the next object of the same script type. That next object is a new run, and an old view never reads it:

var first = Scripts.Find<GuardScript>(guardBehaviour);
// the guard despawns; the relief guard starts and reuses its storage
var relief = Scripts.Find<GuardScript>(reliefBehaviour);
// first.Exists is false and first.Read(...) returns 0;
// relief.Exists is true

Call Scripts.Find again to reach whatever the object runs now. Two views compare equal when they see the same run of a script, before and after it ends.

Following changes

Observe calls your method with the new value each time the variable changes:

m_Watch = view.Observe(view.Definition.Health, ShowHealth);

It exists for Number, Flag, Var<Vec3>, Var<Rotation> and Var<Vec2>.

  • It runs at most once per frame, after every script’s On.LateUpdate, and only when the value differs from the value at the previous check. It does not run for the value the variable held when you called Observe; read that with Read.
  • You end it with Dispose(), usually in OnDestroy. Disposing twice does nothing.
  • It ends by itself when the script ends. IsActive becomes false and your method is not called again.
  • It ends when your component is destroyed. When the method you passed belongs to a MonoBehaviour or another Unity object that has been destroyed, the next check ends the observation instead of calling it. A lambda is not a Unity object, so dispose a lambda’s observation yourself.
  • A method that throws is reported once. The exception is logged as an error, that observation ends, and every other observation still runs.

Observe on a script that has already ended returns an observation whose IsActive is false, and writes the same one warning a read does.

Changing a script’s state

There is no write through a view. To change another script’s state, send it a message and let its own On.Message blocks change it:

// in the script's Build():
On.Message(nameof(Heal), Health.Add(25));

// in C#:
playerBehaviour.Send(PlayerScript.Heal);

Heal here is a const string the script declares, so the name is written once. The script decides what a heal does, including any limit it applies.

The object’s own script

LunyScriptBehaviour also reads the variables of the script on its own object, through GetNumber, GetFlag, GetVec3, GetRotation, GetVec2, GetEnum, ReadText and GetAsset:

var script = (PlayerScript)behaviour.Script;
var health = behaviour.GetNumber(script.Health);

These reads throw a LunyScriptUsageException before Awake and after the object is destroyed, where a view returns a default. Use a view for an object whose script can end while you still hold a reference to it.
