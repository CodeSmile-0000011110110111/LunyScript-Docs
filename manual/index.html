Manual API Reference

Manual

Every page here covers one LunyScript feature. Each one opens with the shortest script that uses the feature, explains what the feature is for, then lists what you can write. Each page ends with links to the next page and to the generated API Reference, which carries the full signature of every member.

Start here

  • Introduction — one Build() body, the API in highlights, and one line from each feature.
  • Writing a script — the class you write, the method you override, and how a script reaches a game object.
  • Compile-time checks — the mistakes the compiler reports on the line, from LUNY001 to LUNY009, and what to write instead.
  • Debugging a running script — the Debugger window: which blocks ran, the branch each If took and how long ago, and changing a value while the game runs.
  • Writing to the Console — Debug.Log, Debug.Warn and Debug.Error, and the variable, value, script and object each line names.
  • AI agent skills — the skills that teach Claude Code, Codex and Grok to write LunyScript, and the skill links the Install LunyScript AI Skills box asks to install.

Values and state

  • Variables and values — numbers, flags, text, vectors and rotations, the arithmetic on them, and how two objects share one value.
  • Lists and maps — fixed-capacity collections and the loop that visits them.
  • Random numbers — named streams that produce the same draws again from the same seed.
  • Reading scripts from C# — find the script an object runs from a MonoBehaviour, read its variables and follow their changes.

Running blocks

  • Events and object lifetime — the object’s lifetime and ticks, and creating or removing objects.
  • Messaging — On.Message, sending from C#, and asking the authority to act.
  • Talking to other scripts — read another object’s script, ask it with a request it declares, hear its events, share its gates, and run a script once per game.
  • Object pools — reuse copies of a prefab: declare a pool, spawn from it, despawn back into it, and cap how many it holds.
  • Flow: conditions, timed work and routines — branching, repeating on a cadence, running steps in order or at the same time, and waiting between them.
  • Choosing between options — score several actions each frame and run the winner.
  • State machines — keep an object in one of a few named states, with what each state does on entry, while current and on exit, and when it moves.
  • Behaviour trees — try options in order and fall back when one fails: Task and Check leaves, composites, wrappers and Repeat, started as one tree.
  • Time, pausing and gates — the game clock, which scripts keep running while the game is paused, and suppressing input or camera writes.

Moving objects

  • Transform — writing position, rotation and scale directly, and walking the hierarchy.
  • Motion — moving an object through its CharacterController or its Rigidbody.
  • Navigation — sending an object along a route around walls, pausing and stopping it, and reading whether it arrived.
  • Follow and lead — keeping an object within a range of another, leading another to a place and waiting when it falls behind, directly or along routes.
  • Physics — collision and trigger contact, and Other, the collider on the far side.
  • Collision queries — casting a ray or a shape from an object, testing the volume around it, and drawing what each query tested.

Drawing objects

  • Showing, hiding and tinting objects — stop drawing an object while it keeps running, flash its colour, and write a number its shader exposes, without changing the material.

Players, content and peers

  • Player input — per-player actions, action watches, local players pairing and leaving, rebinding and the cursor.
  • Cameras and viewports — which camera a view renders, split-screen viewports, and what a camera rig follows.
  • User interface — binding values to named UI Toolkit elements, reacting to buttons and controls, placing a fragment, keeping a label over a point in the scene, and opening a menu.
  • Looking at and using objects — what each local player focuses with the cursor or the centre of the view, a highlight shared by every player, a prompt per player, using an object once per frame, and preparing objects in the Editor.
  • Binding scene objects — Bind.Object(): the object the Inspector assigns or the scene’s object of that name, and a binding with no object.
  • Assets and operations — declaring the assets a script uses, loading them, and observing work that takes more than one frame.
  • Custom data and files — a struct of game data each object copies, data read from an asset, and text, JSON, PNG and WAV files.
  • Saving progress and settings — documents that keep variables between sessions on the player’s device, and changing them between versions.
  • Networking and cloud save — reading the session, synchronising state at a chosen cadence, authority events and stored values.
